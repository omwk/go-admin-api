# F1 Account Lifecycle Implementation Plan

**Goal:** Implement all twelve acceptance cases in `docs/tasks/F1-account.md`.

**Architecture:** Keep identity services behind bounded repository ports. Reuse persistent session revocation, admin grant checks, and F3 channel delivery. Authentication tokens persist as SHA-256 hashes; the approved F3 encrypted outbox retains the original link for stable delivery and retries.

**Tech Stack:** Existing Go, Gin, GORM, PostgreSQL, Redis and bcrypt dependencies.

**Spec:** `docs/tasks/F1-account.md`; `docs/design/admin-framework.md` sections 7–8.

## Constraints

- No new dependencies, no edits to merged migrations or design conclusions.
- Passwords: at least eight characters, letters and digits, maximum bcrypt input 72 bytes; last five passwords unavailable; expire after 90 days.
- Tokens: 32 random bytes, SHA-256 persistence, expiry and atomic use limits.
- All identity queries bind tenant and user ownership; self endpoints require no admin permission.
- Forgot uses uniform 202 responses and independent IP/account limits.
- Preserve current session after password change; revoke all after reset/logout-all.
- E.164 normalization and account classification happen before database lookup.
