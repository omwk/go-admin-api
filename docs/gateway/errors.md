# 对外错误与重试

对齐 M8-review §7 与已落地 `gateway.PublicError`。401 的 80101/80102/80103 文案统一为 M8a 已接受的“应用凭证不可用”，分类 code 保留。客户端根据 HTTP + code 判断，不解析文案。错误无业务 data，不带内部 Cause/SQL、URL、key 命中原因。

| 场景 | HTTP/code | 安全文案 | 重试建议 |
|---|---|---|---|
| 参数、重复 query、非法编码 | 400/10001 | 请求参数无效 | 修正再签名，不自动重试 |
| 请求体超过 1MiB | 413/10001 | 请求体超过限制 | 减小请求 |
| 缺头、应用不存在/停用、格式不合法 | 401/80101 | 应用凭证不可用 | 检查配置/应用状态 |
| 签名错误、key 到期/吊销 | 401/80102 | 应用凭证不可用 | 切换有效 key；不循环重试旧 key |
| 时间窗超限、nonce 重放 | 401/80103 | 应用凭证不可用 | 对时，生成新 nonce/时间戳/签名 |
| IP 白名单不符 | 403/80105 | 当前来源未获授权 | 修正来源或申请变更 |
| 路由授权缺失/到期、owner 权限不足 | 403/80104 | 未获授权访问此接口 | 申请授权，禁止自动重试 |
| 未知/private/disabled/错误方法路由 | 404/80201 | 接口不可用 | 核对已发布能力；当前 dispatcher 不承诺 405 |
| 订单不存在或超出应用/owner 资源范围 | 404/10003 | 资源不存在或不可访问 | 核对公开 ID/授权，不探测内部资源 |
| 幂等键冲突/正在处理/版本冲突 | 409/10006、10004、10409 | 幂等键与请求不一致 / 请求正在处理 / 资源版本冲突 | 管理写接口按具体契约处理；公开只读 v1 无客户端幂等结果重取协议 |
| 自身 QPS/突发超限 | 429/10005 | 请求过于频繁 | 至少等待 Retry-After 秒，加随机抖动，再生成新签名 |
| API 日/月配额耗尽 | 429/10005 | 调用配额已用尽 | 等 UTC 复位或申请额度，不做立即退避重试 |
| 上游鉴权/网络/5xx/非法结果 | 502/80301 | 服务暂不可用 | GET 有界指数退避，建议最多 2 次；现行订单读无平台回源 |
| 上游 429/共享上游桶不可用 | 503/80301 | 服务暂不可用 | 有 Retry-After 则遵循；不能当自身配额耗尽 |
| 执行超时 | 504/80302 | 服务响应超时 | 先确认调用结果，再决定是否重发；新 nonce |
| nonce/授权/配额/计量 DB 或 Redis 不可验证 | 503/10002 | 服务暂不可用 | fail closed；有界退避，不能退回免费直连 |
| 内部未知异常/解密故障 | 500/10002 | 服务处理失败 | 联系支持，提供服务端 trace_id |
| M8 balance 未就绪 | 503/10002 | 服务暂不可用 | 等待余额能力正式发布，不轮询重试 |

所有失败不产生成功计量。已准入请求即使业务失败也保留准入配额。成功持久化后响应丢失仍会计量；重发 GET 会成为新逻辑调用。M8 不启用钱包/套餐错误，也不将 API quota 映射为套餐耗尽。

## 限额元数据

429 的 details 仅含 `limit_type`：`global/client/route/client_route/daily_quota/monthly_quota`；不泄露内部桶键。响应头 `X-RateLimit-Limit` 为约束桶 burst 或配额上限，`X-RateLimit-Remaining` 为剩余量，`Retry-After` 为向上取整的正整数秒。

当前协议没有 `reset_at` JSON 字段或 `X-RateLimit-Reset`。日配额在下一 UTC 00:00:00 复位，月配额在下一 UTC 月初 00:00:00 复位；`Retry-After` 给出到该时刻的秒数。演练输出从 UTC 日历边界计算的 `reset_at`，并验证与服务端 Retry-After 相符。两种配额同时耗尽时，返回阻塞更久的月配额。QPS 桶的 Retry-After 表示预计下一令牌等待时间，不保证并发竞争后的必然准入。

用调用返回的 `trace_id` 和 `X-Call-Id` 联系支持，保留时间/HTTP/code；不收集 secret、签名头、body、完整 URL/query 或联系方式作为故障日志。
