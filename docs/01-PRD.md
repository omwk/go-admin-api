## 0. 阅读方式

- 每条需求有唯一 ID：`REQ-<域>-<序号>`。**提交信息、PR 描述、测试用例名都必须引用 ID。**
- 优先级：`P0` 不做则业务闭环断裂；`P1` 影响体验/效率；`P2` 可延后。
- 「验收要点」是**可执行断言**的摘要，具体命令在各里程碑任务卡里。
- 带 ⚠️ 的条目是与上游平台强耦合、易变的点，实现时必须走适配器 + 映射配置，禁止硬编码。

## 1. 背景与目标

### 1.1 现状痛点

1. 多个电商平台、多个店铺，订单/商品分散在各自后台，人工汇总，易漏单。
2. 平台 API 字段经常变、文档滞后，写死的解析代码一改就崩。
3. 给客户报价靠截图和 Excel，价格版本混乱，客户看到的和最后成交的不一致。
4. 手上有一批外部实用 API，散落在脚本和 Postman 里，无法统一鉴权、限流、计量，更无法对外收费。

### 1.2 目标（按优先级）

1. **一个后台管所有店铺**：订单、商品、库存统一视图。
2. **上游变化不致命**：字段变更可被检测、隔离、修映射、重放，不需要改代码。
3. **报价可管控**：同一商品对不同客户不同价，分享出去的页面内容冻结、可追溯。
4. **API 资产化**：外部 API 统一接入、内部可用、外部可售、用量可计量。

### 1.3 非目标（本版本明确不做）

| 不做 | 原因 |
|---|---|
| 自研前端框架 / 设计系统 | 复用现成 admin 模板（SoybeanAdmin / vue-element-admin） |
| 微服务、服务网格、K8s 编排 | 模块化单体足够；拆服务留了边界 |
| 自建支付渠道（微信/支付宝直连） | 先人工充值 + 兑换码，支付在 M10 之后评估 |
| 直播/内容/营销玩法（优惠券、秒杀） | 不属于中后台范畴 |
| 跨境物流轨迹、清关 | 后续独立模块 |
| 移动端 App | 分享页做 H5 自适应即可 |
| 完整的客户账号体系（客户登录、历史订单） | MVP 用匿名签名链接 |
| 浏览器自动化抓取（Playwright 登录保活） | 只留扩展点，稳定性和封号风险高 |
| 多语言 / 多币种结算 | 数据模型留 `currency` 字段，MVP 只跑 CNY |

## 2. 角色

| 角色 | 说明 | 关键诉求 |
|---|---|---|
| 超级管理员 | 系统所有者 | 全部权限、租户配置、平台接入 |
| 运营 | 管店铺、商品、订单 | 同步状态可见、能手动重试 |
| 销售 / 客服 | 给客户报价、分享商品 | 快速生成报价单和链接 |
| 财务 | 充值、对账、开票 | 账单准确、可导出 |
| 外部客户 | 收到分享链接的人 | 打开即看、价格清晰、能留言 |
| 外部开发者 | 购买 API 的合作方 | 文档清楚、密钥可控、用量透明 |

| REQ-SYS-010 | 定时任务管理：查看、暂停、手动执行 | P1 | 任务列表含上次结果与耗时 | M3 |

## 4. 业务规则（不可违反）

| ID | 规则 |
|---|---|
| BR-001 | 所有金额用 `int64` **最小货币单位**（人民币为分），禁止 float/double；跨币种禁止直接相加 |
| BR-002 | 所有时间存 `timestamptz`（UTC），接口传输 RFC3339，展示层按店铺时区转换 |
| BR-003 | 外部数据唯一键：`(tenant_id, platform_id, shop_id, resource_type, external_id)` |
| BR-004 | 同步写入必须幂等：`payload_sha256` 相同则跳过；不同则按 `updated_at` 比较，旧数据不覆盖新数据 |
| BR-005 | 凭据明文永不出服务端：接口不返回、日志不打印、异常不携带 |
| BR-006 | 已生成的分享快照不可变；改价只能新建链接或切换到 `live` 模式 |
| BR-007 | 价格解析优先级：报价单条目 > 商品原价；两者都无 → 按店铺配置（询价/隐藏） |
| BR-008 | 钱包扣减必须原子（条件 UPDATE），且每笔都有唯一 `idempotency_key` |
| BR-009 | 对外可见的实体用软删除；原始报文与流水类数据只追加 |
| BR-010 | 订单状态只能按白名单流转，非法流转拒绝并记录 |
| BR-011 | 任何对外暴露的接口（分享页、开放网关）必须限流 |
| BR-012 | 映射版本发布后不可修改；修正只能发新版本 |

## 7. 验收总则

一个里程碑算「完成」，必须同时满足：

1. `make lint test` 全绿；
2. 该里程碑所有 P0 需求的验收要点有对应的自动化测试（集成测试可用 `TEST_DATABASE_URL` 跳过）；
3. 数据库迁移可 `up` 可 `down`，重复执行不报错；
4. 新增/变更的接口已更新到该里程碑任务卡的接口表；
5. 输出「偏差说明」：与 PRD/架构不一致之处，逐条列出并说明原因；
6. 人工抽查 20% 的验收要点，实际跑命令确认。
