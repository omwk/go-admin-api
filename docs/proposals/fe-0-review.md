# FE-0 · 前端 Gate A 设计评审

- 日期：2026-11-10；状态：待人工裁决；本稿为提案，不替代已有 ADR。
- 基座：Vben Admin v5、Vue 3、Vite、TypeScript、pnpm monorepo；具体 v5 tag、UI 适配分支及浏览器支持范围尚待锁定。
- 范围：六项设计选择与前置契约评审；本次仅新增本文，不初始化工程、不安装依赖、不改变后端契约。
- 边界：路由、按钮、字段显隐均为体验控制；每次请求仍由后端校验会话、权限、租户和数据范围。
- 工作量口径：人日，按熟悉 Vue/Vben 与现有 Go 服务的人员估计，含对应回归；各题共享客户端、工程与测试成本，不能直接相加。新增依赖仅为待审批候选。

## 2. 实现风险（按严重度）

| 级别 | 触发条件 | 影响 | 规避 |
|---|---|---|---|
| P0 | 三段注册表与四段 PII 码不一致，或用 is_super 绕过前端全部判断 | 普通角色无法正确授权；超管界面误导，甚至错露字段 | C01 先裁决；精确比较服务端权限集合，服务端始终复核 Scope |
| P0 | 多标签重复刷新、503/响应丢失后继续用旧 refresh | 超过 30 秒触发整族撤销；写请求重复执行 | 同族刷新协调、有限等待 20109、请求只重放一次；无法取得新 token 时重新登录 |
| P0 | PII 进全局缓存、keep-alive、埋点，或退出后旧响应写回 | 超过重认证窗口仍显示明文，跨账号残留 | 局部内存、到期/隐藏/退出即清空、认证代次校验、禁止敏感请求自动预取 |
| P0 | 分享应用复用管理 DTO/请求拦截器，公开入口转发任意 API | 内部字段外泄，匿名页面触发管理认证或扩大暴露面 | 独立公开 DTO/client/构建与入口白名单；公共入口验证 Origin、Cookie 和日志脱敏 |
| P0 | 用 number 运算或 JSON.parse 后再转 BigInt | 金额与 ID 已不可逆失真 | 解码前保留整数原文；生成类型与运行时数值适配一起验收 |
| P1 | 对所有 GET 自动重试/预取，尤其匿名根准入 | 一次打开重复消耗 max_views；弱网重试扩大拒绝 | 按 operation 规定副作用与重试，根准入单次触发；验密不扣次数，成功后再根准入一次 |
| P1 | 2xx + X-Authz-Invalidation: pending 被当失败，或一次性秘密签发被通用重放 | 已提交授权重复写；分享链接回执成功但秘密不可恢复 | 成功状态与待失效提示分开；一次性秘密回执专用交互 |
| P1 | 深链接先匹配 404，权限撤销后保留旧路由/缓存 | 刷新误报 404，旧页面继续提供无效操作 | 首次导航等待授权加载；重拉后按差集移除路由、标签与缓存，拦截过期响应 |

## 3. 方案对比

### Q1 动态菜单与路由

| 方案 | 做法 | 优点 / 缺点 | 影响面与后端是否变更 | 工作量 | 推荐 |
|---|---|---|---|---|---|
| A 本地组件白名单 + 事件触发重拉 | 静态基础路由；后端菜单经适配后动态注入；登录、显式刷新、窗口恢复焦点及过期的导航时重拉 menus；自身授权修改后立即重拉 | 沿用现有契约、成本低；持续停留页面不会自动感知远端改动，不承诺前端 5 秒更新 | FE 路由/菜单/标签/缓存适配；**后端运行时无需变更**，菜单 component 与页面注册表需联调对齐 | FE 2–3；BE 0 | **FE-1 推荐** |
| B 同一白名单 + 授权版本轮询 | 聚合响应增加不透明 authz_version 或 ETag；活动页定期检查，变化时整包重拉；多标签选一个检查者 | 流量可控、能定义 UI 收敛时限；需处理版本与内容原子一致及轮询负载 | **需后端变更** MenusData/条件请求或轻量版本接口；不得直接暴露 Redis key；FE 增版本协调 | FE 3–4；BE 1–2 | 有明确页面时限后推荐；若要求页面约 5 秒更新，须另核算检查周期及后端传播预算 |
| C 同一白名单 + 服务端通知 | SSE/WS 只推授权失效信号，客户端仍重拉完整聚合；断线以焦点/轮询补偿 | 感知快；长连接、重连、撤销与多实例广播复杂 | **需后端变更**通知协议、认证与重连语义；增加部署连接支持 | FE 4–6；BE/运维 4–6 | 首版不推荐 |

所有方案共享下列路由纪律：

1. 构建时从本地 views 建组件映射，将 sys_menu.component 的逻辑键映射到受控组件；禁止按服务端字符串导入任意文件、远程脚本或执行 meta。dir 映射固定布局，menu 映射页面，button 不注册路由，link 只允许已批准的 HTTPS 外链并使用 noopener/noreferrer。
2. 路由 name 使用稳定菜单 ID 命名，keep_alive 对应受控组件身份；meta 仅白名单映射标题、图标、缓存等，不能覆盖认证守卫。拒绝重复 path、保留路径覆盖、非法 redirect 与 redirect 环；redirect 只能指向本轮可访问的内部目标，外链另走 link 流程。
3. 隐藏详情路由由本地目录声明父页、path 模板及所需精确权限，动态注册；不请求 /admin/menus 的全租户配置树补权限。没有授权的父菜单不被前端“补回”。
4. 首次深链接导航先完成 refresh/menus 初始化再判断兜底：本地已知页面但缺权限显示 403；无本地页面定义的 URL 显示 404；后端资源 404 保持统一“资源不可用”，不反推是否越权。返回了菜单却找不到组件时显示“页面配置不可用”并记录安全菜单 ID，归配置故障，不伪装成用户无权限。
5. 重拉结果一次性替换 user/menus/permissions，移除旧动态路由、已撤权标签及 keep-alive/查询缓存；当前页失权转 403 或首个可访问页。503 显示依赖不可用，暂停敏感操作，不把旧权限当作离线授权。

### Q2 认证与会话

| 方案 | access / refresh 存放及刷新恢复 | 优点 / 缺点 | 影响面与后端是否变更 | 工作量 | 推荐 |
|---|---|---|---|---|---|
| A 双 token 仅内存 | 二者均不持久化；页面重载后重新登录 | 落盘暴露少；体验损失明显，内存也不能防 XSS | FE 认证状态；**后端无需变更**，继续 JSON bearer | FE 1–2；BE 0 | 高约束环境备选 |
| B access 内存 + refresh sessionStorage | access 不持久化；refresh 按标签会话保存，重载用其恢复；不提供“记住登录”承诺，也不假定浏览器会话恢复时必已销毁存储 | 适配现有后端且可恢复；refresh 对同源 JS 可读，需明确接受此风险；双 token 都放 sessionStorage 只会增加 access 持久化面 | FE 专用存储、会话协调、刷新队列；**后端无需变更**；禁将 Vben store 自动持久化到全部认证字段 | FE 2–4；BE 0 | **FE-1 推荐**，生产是否接受须裁决 |
| C access 内存 + refresh HttpOnly cookie | 管理认证由同源 cookie 端点或 BFF 承载 refresh；JS 不再获得 refresh 明文 | 减少 refresh 被 JS 直接读取的机会；cookie 仍需 CSRF 防护，不能消除 XSS 发起请求 | **需后端变更** login/refresh/logout、Set-Cookie/清除与响应投影，或新增 BFF；确定 host-only、Secure、SameSite、Path、Origin/CSRF、跨域 credentials 策略 | FE 3–5；BE 3–5；部署 1 | 正式上线前优先评估；不能作为零改动替换 |

刷新、重放与撤销规则不随存储方案改变：

1. 同标签只建立一个 refresh Promise；只有管理业务请求的 401/20102 进入队列。login/refresh/reauth 自身不经过递归刷新；reauth 的 401/20101 是密码错误，不直接把整个管理会话登出。
2. 同一 sid 共享的标签以 Web Locks 协调刷新，锁内先复查认证代次，再决定是否发起轮换；用 BroadcastChannel 在同源内交换代次与成功结果。B 除 refresh 外仅保存非秘密 sid/代次元数据，以便重载后仍能找到同族锁；把新 refresh 更新到参与标签的 sessionStorage，access 留内存，完整 pair 就绪后唤醒队列。C 由浏览器更新 HttpOnly cookie，只同步 access 与代次。JWT sid/本地元数据仅用于客户端分组，不能代替后端验证；不支持该协调能力的浏览器采用独立登录族，不以无锁 localStorage 标志冒充互斥。
3. 复制标签可能复制 sessionStorage，因此不能假定“不同标签一定不同族”；也不把不同登录产生的 sid 强行合并。同源消息按当前账号/族与登录代次校验，既不落日志也不用于跨域分享。
4. 收到 409/20109 仅等待已成功刷新者的新认证状态，不自行再用旧 refresh 发请求；设置有限等待，广播丢失可向同族标签查询最新代次/结果，成功响应丢失、刷新者退出或仍拿不到新凭据时结束队列并要求登录。30 秒是后端宽限上限，不是前端循环重试预算；refresh 返回 503 也可能已经提交轮换，不能盲重试旧凭据。
5. 新 access 就绪后每个原请求最多重放一次；写操作保留原 Idempotency-Key 与相同业务请求字节。被取消、登录代次已变、一次性秘密签发及非幂等/流式请求不自动重放；恢复失败只出现一次登录提示。
6. logout 调用当前族撤销；本地退出即广播该 sid 的登出事件，清 token、路由、查询、PII、待重放队列。其他 sid/账号不冒充已撤销；“全部设备退出”需另有后端契约。logout 503 时显示“本地已退出，服务端撤销未确认”，不声称整族撤销成功。
7. 任一管理请求 401/20103 立即终止当前族并同步同族标签，说明“会话已失效，请重新登录”，不刷新；管理员踢 sid 后最迟在该族下一次受保护请求体现。无需首版推送踢下线通知。503/10002 显示服务暂不可用，不当作密码错或踢下线。

### Q3 权限与数据范围

| 方案 | 做法 | 优点 / 缺点 | 影响面与后端是否变更 | 工作量 | 推荐 |
|---|---|---|---|---|---|
| A 精确权限集合 + 服务端筛选 | 用 menus.permissions 驱动统一 hasAll/hasAny、路由与按钮；字段用对应读取能力门控；列表仅展示服务端返回范围 | 契约已具备、逻辑小；只能提示“数据范围由服务端限定”，无法展示准确部门子树 | FE 权限适配与页面声明；**后端无需变更**，PII 例外 C01 待裁决后接入 | FE 1–2；BE 0 | **FE-1 推荐** |
| B 增加有效范围摘要与受限选项 | 后端返回有效 Scope 提示、可选部门/负责人树；筛选器只展示已批准范围，仍由后端再次校验 | 用户理解空列表/不可选原因；需定义多角色合并和读/管理范围区别 | **需后端变更**范围投影、部门/人员选项 API 及相关列表筛选参数；不能从当前 user.roles 推导，也不能下载全租户树后隐藏 | FE 2–4；BE 2–4 | 用户/角色管理和部门过滤批次推荐 |
| C 资源级能力投影 | 各资源返回 allowed_actions/受控字段能力及安全原因，前端结合全局权限呈现 | 精确减少“能点却拒绝”；每类资源都要维护投影且仍有并发过期 | **需后端变更**各 DTO 与能力计算；FE 增资源适配，不能将投影当授权票据 | FE 3–5；BE 4–6 | 复杂工作流再引入 |

- 权限只按注册表中的完整字符串比较，不把角色 code 当按钮权限，不从 sys_menu 推导接口能力，不实现通配符。x-permission 为空但有 bearerAuth 的平台/文件接口表示没有该附加权限码，仍不是匿名接口。
- is_super 只用于标识展示，不令前端 hasPermission 无条件返回 true；identity.menus 已声明超管收到租户全部权限与合格菜单，直接使用该集合。超管仍可能遇到数据范围、状态、引用、重认证或资源不存在的拒绝，界面按实际结果解释。
- 普通字段未有专门字段权限时，不发明权限码；订单地址与询价 PII 使用专属读取端点，明文不能先拉回再靠 CSS 隐藏。C01 解决前不开放这些功能。
- 部门/本人/自定义是后端行过滤，不是浏览器过滤器；空结果可能是 Scope，不能自动切“全部”。C 方案也不能消除竞态，403 时更新权限/清明文，保留可安全编辑的草稿并说明失败。

### Q4 API 客户端

| 方案 | 做法 | 优点 / 缺点 | 影响面与后端是否变更 | 工作量 | 推荐 |
|---|---|---|---|---|---|
| A openapi-typescript + 薄客户端 | 按 spec/公开边界生成类型，手写少量 operation 适配，统一传输、错误、刷新、幂等与取消 | 符合手写 OpenAPI 为事实源，适配 Vben 方便；仍需维护请求封装，schema 空洞不能自动补齐 | **后端运行时不要求变更；需补齐相关 spec**；前端生成器为新增开发依赖候选，无损数值能力另审批 | FE 2–4；BE 补规范 1–3/批 | **推荐** |
| B Orval 生成客户端 | 生成请求函数，接入统一自定义传输；如选 Vue Query 再批准其运行时依赖 | 标准接口更省手工代码；生成配置、缓存与刷新重试耦合更多，一次性秘密/根准入必须特殊处理 | **后端运行时不要求变更；同样需补 spec 与稳定 operationId**；FE 工具及可选运行时依赖更多 | FE 3–5；BE 补规范 1–3/批 | API 规模扩大后备选 |
| C 手写类型与客户端 | 按已批准 spec 为每个接口维护类型/序列化 | 早期少量接口启动快；改 spec 不能自然暴露漂移，长期重复维护 | **后端无需为该方式变更**，但缺 DTO 仍须批准，不能直接以数据库表充当响应；FE 另建契约核验 | FE 首批 1–2，后续持续维护 | 只适合限时过渡，不推荐作底座 |

统一客户端的具体约束：

1. 传输层同时判断 HTTP 状态和业务 code，保留 trace_id/request_id；正确处理空 204、JSON envelope、直接 CSV 和对象存储下载。多个 spec 的 Envelope/Page 同名类型按域隔离；公开 client 仅含批准的匿名 operation，不从管理端类型裁剪。
2. 错误字典以 conventions §3 与各操作错误说明为源，维护“code + operation 场景 → 提示 key / 可执行动作 / 重试策略”；状态机动作与 i18n 文案分离。新增或变更错误码必须同步前后端契约检查；未知码用安全兜底提示和 trace_id，不原样展示不可信 details、原始上游内容或完整 URL。

| 场景 | 提示与动作 |
|---|---|
| 10001 | 表单安全校验提示；无结构化字段定位时不猜字段 |
| 10006 / 10409 | 前者停止同键不同体重试；后者拉最新版本让用户比较后再提交，不覆盖别人的修改 |
| 20101 / 20104 / 429+10005 | 凭据错、账号锁定、频控分别展示；限流按 Retry-After 等待，不自动轰炸登录 |
| 401+20102 / 401+20103 / 409+20109 | 分别走一次刷新、族失效、等待并发刷新结果；不能统一“token 失效” |
| 403+20107 / 403+20108 | 操作拒绝/范围拒绝；只在 PII operation 的重认证流程中按 C06 提示验证，不对全局 20108 弹密码框 |
| 2xx+X-Authz-Invalidation: pending | 已保存成功，提示授权更新待确认并重拉；不触发写重放 |
| 503+10002 | 依赖暂不可用；普通无副作用读取可有限退避，认证轮换/匿名准入/写操作按各自恢复规则 |
| 匿名 70102 / 70103 | 保持公开统一安全文案；70103 提供密码输入，70102 展示链接不可用，不细分存在/撤销/超次数，也不跳后台登录 |

3. 列表组件内部提供“页码模式/续页模式”能力适配，不强制修改所有线协议：页码模式映射 list/total/page/page_size，默认 1/20，page_size≤100，sort 仅用该 operation 白名单；如角色列表用 -id，不能硬塞 -created_at。
4. 续页模式只提供下一页和已访问页栈，不伪造 total 或任意跳页；opaque cursor 不解码。catalog 声明 cursor 但尚缺精确续页响应，先补规范；账单详情实际用 after + page_size，响应 lines/next_cursor，0 表示结束，应独立适配，不能改叫 cursor+limit 发给后端。
5. 订单当前只支持前 10000 行的 offset 遍历，无 cursor；超界提示缩小筛选或异步导出，不擅自传不存在的参数。筛选、排序、page_size、账号或授权代次变化时清游标和选中项，取消旧请求，并拒收较旧查询代次的结果。
6. 每次用户确认一个逻辑写动作时生成随机 UUID 作为 Idempotency-Key，36 字符满足当前各域最短的 128 字符上限；一个动作的并发点击、网络不确定后重取、认证重放必须保留同键、同方法/路径/规范化请求体与版本。key 不含账号或业务秘密，待完成上下文仅存内存；改输入或冲突后经用户重新确认才生成新 key。
7. billing 所有写操作强制带 key，其他已声明支持的管理写操作也统一使用；认证和一次性秘密按专用协议。非幂等、未知幂等支持或含不可重建流的操作不做通用自动重放。原始请求体不进日志或持久化重试箱。
8. share 签发幂等重放可能只有 id/secret_delivered=true 而没有 url：显示“链接已创建，原链接无法再次取回”，提供显式再生成并决定旧链撤销；不自动换 key 再签一条，也不把回执成功解释为可复制链接。
9. 所有 *_cents、bigint ID/游标与计数的精度在 JSON 解码前处理；建议使用经批准的无损编解码与生成器 int64 映射，内部用精确十进制值/BigInt，金额以整数分运算。发送时仍是普通十进制 JSON 整数，不能变字符串、浮点或科学计数法；格式化金额不经有损 number 中转，币种分组，禁止跨币种求和。
10. 时间线上传 RFC3339 UTC，业务日/月保留 date 或 YYYY-MM 语义；店铺时间按店铺 timezone 展示，未知时标注 UTC。日期筛选按选定时区的 [from,to) 转 UTC，不能用浏览器时区悄悄改账单 UTC 月边界。enum 从 spec 生成并做穷尽映射，未知值保守展示，禁止“默认可操作”。

### Q5 敏感数据与对外页面

先固定交互边界：**推荐按需密码弹窗，路由守卫只作辅助**。弹窗对单次“查看完整信息”动作调用 POST /api/v1/auth/reauth，成功记录 reauth_at/expires_at，再调用具体地址/询价 PII 端点；取消即继续看掩码。另一个可行方案是独立敏感详情路由加进入守卫，适合密集审核，但仍必须逐次调用后端且在路由停留期间到期清空，不能只在进入路由时验一次。二者均无需新增后端接口，弹窗 FE 1–2 人日，独立路由 FE 2–3 人日；C01 仍是共同前置。

- 五分钟按后端定义为严格小于，刷新 token 保留族 reauth_at，新登录不继承。倒计时只是提示；本地到期保守清空、标签隐藏/页面离开/关闭弹窗/登出即清空，再次显示重新走授权读取。明文不入全局 store、持久化、keep-alive、搜索参数、导出、SSR/Service Worker 缓存或埋点；卸载/失效后的在途响应不能恢复显示。
- 每次查看均请求专属端点并触发后端审计，权限撤回、20108、404、密钥/审计故障时不展示任何部分字段。重认证成功后同一动作至多自动重试一次；继续拒绝则停止，不循环要求输入密码。刷新后丢失本地计时状态时允许重新认证，不能凭猜测延长窗口。
- 导出先拿 export_id，再按产品 GET /admin/exports/{id} 或订单 GET /admin/orders/exports/{id} 查询；只在 succeeded 且有 download_url 时下载。download_expires_at 是签名过期时间，expires_at 是对象保留期，签名最长 1 小时、对象保留 24 小时，二者不能混用。
- 下载失败/签名到期时，用户可触发一次重新查询状态并取得新签名；owner/权限拒绝不再重签，对象 expired 则显示“重新创建导出”并经确认生成新写动作。跨域浏览器直接下载未必能让 JS 观察状态，未配置存储 CORS 时不能承诺自动识别每种失败；始终提供手动重取入口。
- 对象存储请求不携带管理 Authorization，预签名 URL 不存日志/统计/持久缓存。订单 CSV 固定不含 PII；询价 export 是单页元数据 CSV，独立处理，不能因有 PII 查看权限就增加列。

公开页面的应用边界有三种方案：

| 方案 | 做法 | 优点 / 缺点 | 影响面与后端是否变更 | 工作量 | 推荐 |
|---|---|---|---|---|---|
| A 管理 SPA 内的公开路由 | /s/{token} 绕开管理守卫，独立匿名 client，但与 Vben 同构建、同源 | 复用最多、部署简单；管理依赖/拦截器容易误入公开包，发布和同源存储边界难隔离 | **API 无需变更**；仍须配置公开入口路由白名单、Cookie/Origin；FE 守卫/依赖边界需额外验证 | FE 2–3；部署 1 | 受控预览备选，公网首版不推荐 |
| B 同 monorepo 两应用、不同构建/域 | apps/admin 用 Vben；apps/share-h5 用轻量 Vue 页面，独立 dist/域名/入口；share API 反代到该公开域的同源路径 | 共享纯展示能力且隔离管理认证、包体与发布；多一套构建/部署 | **默认不改业务 API**；需后端/入口配置确认精确 HTTPS Origin、外部 Host、可信代理和 Cookie；若部署无法满足现有同源要求，必须另审后端变更，不能放宽校验 | FE 4–6；部署/联调 1–2 | **公网推荐** |
| C 独立仓库与应用 | 管理端仍为 Vben monorepo；分享站独立发布，只依赖版本化公开契约/纯展示包 | 责任和发布隔离最强；契约/通用包发布、升级回滚成本更高 | **API 原则上无需变更**；同 B 的入口配置，加跨仓契约分发；任何跨源 API 接法仍受 Origin/浏览器 cookie 限制 | FE 6–9；部署/联调 2–3 | 团队/发布节奏分离后再考虑 |

B 的复用与公开流量约束：

1. 可以复用币种/整数金额/时间格式化、无业务状态的展示组件、公开错误文案与独立批准的 PublicItem 等类型；不能复用管理 store、token 刷新、RBAC 菜单、PII 明文模型、admin client、Vben 布局或成本/精确库存等内部 DTO。禁止以 Pick/Omit 管理 DTO 实现公开契约。
2. /s/{token} 是 H5 页面路径，不是当前 API 路径。签发首次回执 url 是相对 API 地址，前端需在批准的 /api/v1/share/{token} 模式内提取路径参数，再与配置的公开站点 origin 构成 H5 地址；不得信任任意返回外链，也不回查列表恢复秘密。
3. share_access 是后端发放、最长 2 小时的 HttpOnly/Secure/SameSite=Lax、host-only cookie，Path=/api/v1/share；浏览器不能转存成 JS token。公开站点同源转发精确允许的匿名路径，拒绝该站点的 /admin、/auth、/open、指标和内部文档路由；保留经批准的 Host/可信代理语义，不采用无条件改写 Origin。
4. 根准入 401/70103 才展示密码门；verify 成功后执行一次根准入，根成功才有详情访问资格。max_views 计根准入次数；路由预取、焦点刷新、通用 GET 自动重试都不能触发它。详情和询价继续接受实时主库授权；503 不回落到旧报价缓存。
5. 询价按同源 HTTPS Origin、JSON、小于等于 16KB、空 website 蜜罐、准入至少 2 秒及速率约束实现；不带管理 Authorization，也不传 tenant/owner/customer/status。只处理 submitted=true 回执，成功后清表单，不建立匿名查询 PII 页。
6. 当前 PublicItem 无图片/富文本/备注等字段，不从管理商品接口补齐；成本、精确库存、客户名和原价保持既定公开白名单。图片/富文本需 DTO 与内容来源再审批；公开媒体已经下载不能回收，界面不许承诺撤销可删除客户已保存内容。
7. HTML/代理/API 的 no-referrer 与 no-store 策略、公开路径参数在网关/CDN/日志/错误采集中的脱敏必须联调验收；不能只清浏览器 console。host-only cookie 与独立域不代替服务端授权，也不代替询价的 Origin 防护。

    frontend/
      apps/admin/               Vben 选定的一个 UI 分支
      apps/share-h5/            独立公开站点
      packages/api-admin/       各管理域生成类型与适配
      packages/api-share/       仅批准的匿名操作与公开 DTO
      packages/domain-format/   无损金额、币种、时间等纯函数

- 先锁定 Vben v5 tag/commit、单一 UI 分支、Node/pnpm 与 lockfile；沿用所选模板必需的 workspace 内部包/构建配置，目录名与 upstream 的对应关系在实施卡记录，不能把上图当成可直接启动的裁剪版。新增生成器、无损 JSON、E2E 等依赖在实施卡逐项批准。
- 多环境分别配置管理 API baseURL、公开站点 origin、公开 API baseURL；推荐各站点使用同源相对路径反代。构建时 VITE_* 或启动时加载的公开配置都不是秘密载体；不放 DB/JWT/HMAC/存储密钥。环境配置校验 origin/协议与批准前缀，CORS 必须明确允许必需头并 expose Retry-After、X-Authz-Invalidation 等前端需读取的头，不能配任意 credentials origin。
- 两应用分别输出版本化静态产物、独立发布与回滚，HTML/运行配置短缓存或不缓存，带内容哈希的静态资源长缓存；每个站点只对自身页面做 history fallback，API 错误不能回落成 index.html。管理端不向公开端注入运行配置/存储。
- OpenAPI 同步以 spec 为输入：固定生成器版本、域命名空间、生成选项与来源 SHA/摘要，生成文件禁止手改；CI 每次相关 spec 改动重新生成并检查差异，再对消费者 typecheck。路径/请求/响应/required/enum 变化要有兼容检查；HTTP 采样/集成契约测试弥补“类型生成通过但服务端没按 spec 返回”的盲区。
- schema 只有 object/空 data/description 时生成结果不具约束力，应阻止对应新页面准入；不能用类型断言掩盖。跨文件 ref（order→catalog、share-access→share-inquiry）必须一起解析；operationId 缺失/重名在生成检查中报出，不能靠不稳定函数名对接。
- 同仓 spec 或前端/共享包/lockfile/相关 CI 改动都触发前端检查；后端认证/DTO 改动须同步 spec，由后端契约检查保障，不能只在前端目录变化时检查。跨仓 B 需在后端发布前对锁定前端版本验证，并生成可审查升级差异，不能靠定期手动查看。

| CI 层次 | 范围与触发 | 目标耗时（预算，非实测） |
|---|---|---|
| PR 静态与契约 | frozen-lockfile 安装、lint、生成差异、schema 完整性、typecheck、公开依赖边界；测试无损整数往返、分页适配、错误/刷新状态机 | 缓存命中 2–4 分钟 |
| PR 构建 | 两应用生产 build，核对公开入口与产物不引入 admin client/配置；即使分享页尚未交付，也构建当期实际应用 | 3–5 分钟，可与测试并行 |
| PR 确定性 E2E | 首版 Chromium：登录→菜单→列表、深链接/403/404、单标签与复制标签并发刷新/20109/响应丢失、sid 撤销；PII/分享上线时加入到期清空、验密准入次数、失效拒绝和导出重签 | 3–5 分钟，PR 关键路径目标 6–10 分钟 |
| 后端联调契约 | 认证/spec/相关 handler 变更必跑真实 Go API 的隔离 DB/Redis 冒烟：请求/响应结构及直接调用权限拒绝；mock 只覆盖网络故障和时钟边界，不能证明后端鉴权 | 计入上述预算；超时先记录 job 实测再裁决 |
| 夜间/发布前 | 支持的多浏览器、完整业务 E2E、公开域 Host/Origin/Cookie/入口白名单与日志脱敏检查；容量/统计测试用显式开关 | 10–20 分钟目标，容量另排 |

计时目标不是容量断言，不写“机器必须几秒内完成”的 PR 测试；前端时间边界用可控时钟，等待具体状态。Go 既有 CI/race 和集成测试分组守卫继续独立执行，新增前端 job 不挤入或替代后端测试分片；本次文档任务没有执行这些未来命令。

## 4. 未来 2 个里程碑的坑（仅列）

此处 FE-1/FE-2 是建议批次名，尚非已批准里程碑。

- FE-1：首次深链接先落 404，或只有菜单却没有已登记组件。
- FE-1：复制标签共享旧 refresh，成功响应丢失后把 30 秒宽限用成重试循环。
- FE-1：生成类型把 int64 变 number，用户 ID 与金额在传输层已失真。
- FE-2：部门选择下载全租户数据，角色授权页又缺关联回读接口。
- FE-2：PII 权限语法冲突未解决，或 keep-alive 留住已过期明文。
- FE-2：分享签发管理沿用通用重放，秘密未送达时 UI 仍假设能取 URL。
