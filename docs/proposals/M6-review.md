## 3. 方案对比

工作量为单名熟悉项目的 Go 工程师人日，含对应单元/集成/故障验证；共享接线与数据契约会重叠，不直接把六行相加。下述新增字段、权限、端点都只列影响面。

### Q1 分享令牌与访问控制

现状依据：M6 §5/T6.5/T6.10；06 §3；M1 ADR-011/012/014；internal/kernel/httpx/middleware.go:33 的日志已使用路由模板，不应误报为应用日志当前直接记录 token。

| 方案 | 做法 | 优点 | 缺点 | 影响面 | 工作量 | 推荐 |
|---|---|---|---|---|---|---|
| A 纯持链访问 | 保留随机 bearer token、有效期/次数与可选密码，每次查持久状态。 | 符合现有七表，分享阻力最小。 | 持链即有权，转发无法辨认；无密码的客户价等同可传播秘密。 | share_link、四个匿名 API、发布提示与撤销审计。 | 2–3 | 仅通用公开目录适合。 |
| B 客户报价密码 + 短期浏览授权 | 沿用随机 token；客户专属报价要求独立渠道交付密码；验证后给绑定链接与安全代次的短期 Cookie，每次仍过持久门禁。 | 不建客户账号，单独泄露 URL 的风险降低；可统一撤销旧 Cookie。 | 链接和密码一起转发仍可读；设备/IP 不能证明联系人身份。 | A + verify、Cookie 签名/版本字段、密码失败预算、一次准入凭据。 | 3–5 | 推荐 M6；必须如实承认转发边界。 |
| C 绑定经验证接收人 | B + 一次性短信/邮件挑战，校验已指定接收渠道后才准入，可限制并发浏览授权。 | 能证明控制该渠道，可区分新的访问会话。 | 仍不能阻止共享验证码、截图；增加渠道依赖、PII 与交付摩擦，超出现卡。 | 接收人验证记录、通道 port、通知、恢复策略；依赖另批。 | 7–10 | 仅保密等级要求高时另批。 |

推荐 B 的具体边界：

1. 生成采用 crypto/rand 的 32 随机字节，Base64URL 无填充恰 43 字符，熵 256 bit；SHA-256 哈希唯一入库，碰撞重取、随机源失败则失败。高熵 token 的确定性哈希用于查找，不改为短数字或含自增 ID 的编码。
2. token 本身不携带可修改权限，库中绑定 tenant_id、customer_id（通用目录可空）、price_list_id/发布版本、明确 SPU/SKU 集合、mode、expires_at、max_views、allow_inquiry 与授权代次。创建者有权限且能管理客户与所有商品才可发布；报价单必须通用或属于该客户，禁止挂别人的报价单。
3. 当前单租户部署用服务端配置的运行租户 + token_hash 做专用解析；tenant/customer/owner 不接受匿名请求指定。未来按已验证域名映射租户时，也不得信任任意 Host 或 tenant header；后续查询全部显式带解析所得 tenant。
4. Cookie 的签名覆盖 tenant/link/授权代次/密码版本/iat/exp/用途，并绑定本次 token 所指链接；有效期取 2 小时与链接剩余有效期的较小值。服务端校验 exp，不以 Max-Age 代替；Secure、HttpOnly、SameSite=Lax、host-only、受限 Path。浏览准入凭据另绑本次访问记录及内容版本，不能充当管理端 JWT。
5. 撤销事务持久写 revoked/revoked_at 并写安全审计；每个根页、详情、verify、inquiry 都重新检查主库状态。缓存只能保存内容，不能授权；旧正缓存、旧 Cookie、迟到回填及 Redis 重启都不能恢复已撤销链接。撤销事务成功即可证明后续准入被拒绝，缓存删除失败另告警，无需等待 TTL。
6. “立即”以授权准入与撤销在同一链接行上的串行点定义：撤销提交后的新准入拒绝，已在撤销之前准入的在途响应可能完成；已下载页面/截图无法收回。若业务要求撤销确认后连在途字节也不能送出，需额外网关排空协议，不宣称本方案已经保证。
7. 客户停用、报价不可用、到期或密码/安全代次变化不得被 Cookie 绕过。客户移交时旧销售立即失去后台范围；已有对外链接是否一并撤销需列入移交策略，不能把销售撤权误当 bearer token 已自动收回。
8. 转发识别只做“新浏览授权/异常频次/粗 UA 变化”等风险信号，不声称识别真实第三方，也不按固定 IP 硬绑手机网络。敏感报价设短期有效期与合理次数；加强身份只有 C。URL 在 path 中仍可能进代理日志和 Referer，需对外入口脱敏、Referrer-Policy: no-referrer、禁第三方埋点及 token 入监控标签。
9. 一次性签发例外：幂等事务仅保存 link_id、状态等安全回执；首次进程内附带 url，重试返回同一业务结果与“秘密已交付，需重新签发”标记，不再发原 token。响应丢失也不能查回明文；重新签发新链并明确是否同时撤销旧链。此语义必须批准后写入契约，不借“加密幂等缓存”变相可恢复保存 token。

### Q2 价格解析与优先级

现状依据：06 §4、PRD REQ-SHR-002/009；模型 §8 price_list_item；ADR-017；internal/bootstrap/catalog_product_write.go:138/170/204。M4 的“归并”实际是 listing/SPU 挂接及 SKU 绑定，不是自动把 SPU 主键折叠重写。

| 方案 | 做法 | 优点 | 缺点 | 影响面 | 工作量 | 推荐 |
|---|---|---|---|---|---|---|
| A 显式绑定有效报价单 | 每链接选一单；客户单或通用单内 SKU → SPU → 允许的 SKU 原价 → 询价，不自动跨单合价。 | 与当前 PRD/七表基本一致，来源可解释，冲突最少。 | 不支持客户组自动继承或“客户单缺一项就补通用单”。 | share 纯解析器、发布校验、条目约束及来源元数据。 | 2–3 | 推荐本期。 |
| B 四来源实时层叠 | 新增组/成员/组报价和默认单关系，逐次按客户专属 → 客户组 → 默认单 → 商品原价解析。 | 运营维护量低，组价变动即时生效。 | 多组冲突、有效期重叠和发布一致性复杂，新增表/查询/缓存维度。 | 客户组模型、价格作用域与优先级、管理接口、缓存失效、审计。 | 5–8 | 只有四来源确认为本期刚需才选。 |
| C 四来源发布成客户有效报价单 | 按 B 的层次在发布时解析，物化一份客户有效单及来源证据，分享只读该发布物。 | 对外结果稳定，运营能预览逐项解释及审批。 | 组价更新需重新发布；仍需组模型、来源版本与发布载体，不能靠现有 tags 冒充。 | B 的配置 + 发布物/来源链/预览冲突报告；保留旧发布物。 | 5–7 | 若必须有组价，优先 C，先批准扩范围。 |

四来源一旦启用，建议采用以下确定规则，而非“谁便宜就选谁”：

- 先排除跨租户、非目标客户/组、非 active、未生效/过期、币种不符或成员不匹配的候选；从客户专属、客户组、默认单、允许的原价依次找首个有效候选。同来源内 SKU 精确项优先于 SPU 项，因此客户 SPU 价优先于组 SKU 价。
- 同一层多组/多单不按最新修改或最低价猜测；发布前报告冲突，要求明确唯一组优先级或运营选单。两份同优先级且同时有效的记录拒绝发布；即使金额相同也记录重复配置。
- MOQ 是约束，不是取便宜价的捷径；已命中专属项但数量不足时提示 MOQ，不回落到组价/原价绕过门槛。零价需显式允许，缺价用 show_price=false + 空价格表达，禁止 0 冒充询价；负数、溢出拒绝。
- 后台解释显示命中来源类型、报价单/条目 ID 和版本、有效期、SPU/SKU、金额/币种、MOQ、未命中/冲突原因与被覆盖候选；snapshot 解释依据冻结来源，不拿当前配置解释旧价。外部只见最终价和公开条件，不见组名、其他客户、成本及内部优先级。
- 金额保持 int64 分与单一 currency；原价只来自同币种 product_sku.price_cents，不从 SPU 平台区间推导、不做汇率转换。原价开关默认关闭；独立纯函数返回“价格 + 来源 + 解释原因”，不在解析器里查库或读取时钟。
- 防归并串价分两层：价格键固定 tenant/price_list/SPU/SKU，校验 SKU 真属该 SPU；发布 SPU 时展开并冻结当时 SKU 成员，share 的 live 也只允许这批 item_refs。新挂 listing 形成新 SKU、SKU 换绑/软删、人工拆分后重挂都不自动进入旧分享或继承旧报价，需重新发布并预览。
- 仅锁 SPU ID 不够：SPU 级报价会自然覆盖后加入的 SKU。稳定成员集与商品身份摘要用于发现成分变化，不依赖“商品编码一样”；已离开原 SPU 的 live SKU 显示不可用，不能追随到新 SPU。snapshot 保留当时名称/价格/身份；M4 既定人工归并机制不变。
- 验收必须包含“客户 A 的 SPU 价 + 新挂入 SKU”“A→拆分→B”“两个客户选同商品”“同层冲突”“客户 SPU 对组 SKU”“默认价缺失/原价关闭”“同数值异币种”，而不只测四个简单命中分支。

### Q3 快照 vs 实时

现状依据：PRD BR-006、ADR-006、06 §1/4.3/6/9；ADR-019 §4/6；M6 明确不做在线下单/支付。M5 是接入平台成交事实，并无 M6 客户创建订单入口。

| 方案 | 做法 | 优点 | 缺点 | 影响面 | 工作量 | 推荐 |
|---|---|---|---|---|---|---|
| A 发布时冻结正式报价 | 生成链接时冻结内容/最终价/条款；有效期内照该报价沟通，重生成发新链接；live 单独标为参考目录。 | 可举证，符合双冻结主旨；100 元报价不会暗变 120 元。 | 运营需主动撤回/重发，不能靠改商品修旧报价。 | share_snapshot、发布来源元数据、再生成响应及新旧链接关系、审计。 | 3–5 | 推荐默认；必须裁决覆盖冲突。 |
| B 每次实时、成交时确认 | live 每次从当下报价单计算；明确“参考价，成交前另行确认”，成交平台订单保存实际金额。 | 更新即时，适合长期目录。 | 两次打开可能不同；不是保价承诺，无本地订单入口就不能声称已经锁价。 | 实时解析/版本回传、价格变动提示、询价所见版本引用。 | 2–4 | 仅明确选择 live 的目录。 |
| C 打开时生成短期报价 | 首次准入生成每次浏览专属快照，例如 2 小时有效，再确认是否接受该价。 | 一次会话内稳定，可表达短期保价。 | 需额外浏览报价记录、到期/再次确认与并发规则；当前一链一快照不够。 | 新浏览报价载体、浏览凭据、询价引用；成交接线另批。 | 6–9 | M6 不推荐，不能只放 Redis 宣称冻结。 |

100 → 120 元的可执行业务约定（建议）：

| 场景 | 三小时后怎么办 |
|---|---|
| snapshot，尚在冻结有效期内 | 仍展示 100 元与冻结条款；按此价格处理询价。要撤回需显式撤销并通知销售，不能改成 120。 |
| snapshot 已到报价/链接有效期 | 不静默延期或换价，返回 70202 或 70102；销售新发 120 元报价，客户重新确认。 |
| live，当前报价变为 120 元 | 当前展示 120，明确更新时间与参考性质；询价附上服务端曾返回的 100 元签名观察回执供核验，销售确认差异，不自动按旧价生成订单。 |
| 外部平台已成交 | M5 的订单明细/支付/优惠原值为成交事实；旧分享只是报价证据，不倒写订单、重算退款或改写平台金额。 |

share_snapshot 建议划清三类数据：

1. 对外冻结投影：schema_version、generated_at、标题、冻结有效期、currency、明确模式/价格性质、商品 SPU/SKU 身份、经批准内容、最终 display_price_cents/show_price、MOQ、对外备注、none/range 库存描述。customer_name 默认移除；original_price_cents 默认不披露，需要宣传用途再显式批准。图片 URL 固定不等于图片字节固定，应使用稳定、可保留的批准媒体；若尚无此能力，列为承诺限制。
2. 内部来源证据：tenant/link/customer 引用、price_list ID/version、条目与价格来源、商品/成员摘要、规则版本、冻结 valid_from/valid_to、公开条款及 payload checksum。必须持久保存；不能靠当前报价单反查还原，也不能放进对外 data。checksum 是完整性索引，不是历史内容的替代品。
3. live 存储：只保存发布时明确选择的 item_refs 与策略/来源约束，禁止“每次展开当前 SPU 的所有 SKU”。返回同版本 DTO，同次价格/商品读一致视图；仅回传版本号不能还原后来被覆盖的价格。建议附签名 price_observation 回执，绑定当前解析的 tenant/link/安全代次及用途，覆盖所选 SPU/SKU、最终价/币种、内容版本与服务端观察时间；不输出内部客户/链接 ID。询价提交原回执时服务端验签并持久保留安全价格证据，篡改/错链接回执不能采信；回执既不授予访问权也不锁价、不证明真人已阅读。未附有效回执时，旧价仅标作客户自述，不能伪称已验证。本期不持久化每次 live 全量内容；完整页面历史举证需选 C 或追加不可变披露记录。

发布时在同一一致性视图读取商品、报价版本和成员集，link/snapshot/安全审计同事务提交；控制商品数、SKU 数与 payload 大小以满足既有短事务预算，生成失败不返回可用链接。live 响应也不能拼接不同读取时点的价格来源；版本在准入前变化时有界重试或明确失败，不返回混合版本。

有效期以“发布时冻结的报价有效期、链接到期取较早者”为准；later 改价/延长报价单不自动改变已发 snapshot。提前禁用/删除报价单采取明确终止访问而非价格回落，冻结内容不变；客户停用和链接撤销同样是访问控制。过期 use_last 只能显式选择为“过期参考”，不能仍作为有效承诺；默认 reject。删除与改价的业务口径需同步 C03。

重生成优先新建 link + 新 token + 新 snapshot，记录来源旧链接及新旧 checksum；旧链接保持原内容，是否同时撤销必须显式选择并同事务审计。若裁决保留同 URL 覆盖，必须保存每版不可变 payload、有效期、披露版本引用并通知变更；现有一行覆盖 + 审计摘要无法证明旧内容，尤其禁止把含 PII 的完整快照塞 audit_log 来补历史。

与 M5 对账是“报价与成交的差异说明”，不是把两套金额强行相等：用经授权的人工关联或未来订单来源引用，明确 tenant、分享/快照版本、订单稳定实例 ID、行身份、币种、数量、MOQ、税/运费/优惠条款；禁止按联系人电话或商品标题自动匹配。报价基数为冻结行单价 × 确认数量（检查 int64 溢出），再按明确条款比较订单行金额与订单级优惠、运费，单列差异。M5 的 goods/discount/shipping/total/paid/refunded 及 delta 保持原值；无税费条款、行映射或不同币种时标“不可自动对账”。M6 只冻结引用与证据，不增加下单/支付/自动改价 API。

### Q4 缓存与匿名访问

现状依据：06 §7/10 要求 private, no-store 及 token+IP 限流；M6 §6 另指定 verify 10/min/IP、inquiry 3/min/IP。no-store 约束客户端/CDN，不自动禁止受控的服务端内容缓存。

| 方案 | 做法 | 优点 | 缺点 | 影响面 | 工作量 | 推荐 |
|---|---|---|---|---|---|---|
| A 全部主库读取 | 每次授权、计数与内容均查 DB，入口另限流。 | 一致性最容易说明，无内容缓存失效问题。 | 热门大目录数据库压力高，随机扫描仍需前置保护。 | 统一准入、批量读端口、反代/API 限流。 | 1.5–2.5 | 小规模首发可用。 |
| B 授权实时 + 内容分域缓存 | 主库判当前授权；仅缓存白名单 snapshot/稳定内容，按版本分 key；动态价格不复用旧授权结果。 | 立即撤销与热点性能兼顾，不让 TTL 决定权限。 | DB 门禁仍有成本，需明确版本、容量和依赖故障行为。 | share cache/准入、限流适配器、版本键、故障测试。 | 3–5 | 推荐。 |
| C CDN 缓存客户报价 | 边缘使用独立浏览授权并在每次返回前复核，或等 TTL/清理传播。 | 极热点读性能好。 | 无实时复核就不能立即撤销；按 URL 缓存极易串权，违反当前 no-store 契约。 | CDN 授权、key/清理协议、Cookie 分域、运维及新 ADR。 | 7–10+ | 本期拒绝启用。 |

推荐 B 的访问顺序为：入口预算与 token 格式检查 → 已确定运行租户内哈希解析 → 有效链接的多维限流 → 当前状态/父引用/密码或浏览凭据校验 → 取得已批准内容 → 同一短事务重验并完成准入计数与访问记录 → 提交后返回。事务不包含 Redis/HTTP；失败不发内容，依赖故障 503/10002，不能回退旧授权。

- snapshot 内容 key 至少分隔 tenant、link、customer/public 标记、授权代次、schema/字段策略版本、snapshot checksum、端点/分页/所选 SPU/SKU。live 还需价格单版本、币种、回退/库存展示策略与成员摘要；难以可靠取版本的数据不缓存最终响应，先按请求计算价格。空 customer 也用显式 public 标记，不能退化成全局 SPU key。
- 键格式可固定为 share:content:v1:{tenant}:{link}:{customer_or_public}:{generation}:{schema_policy}:{content_checksum}:{request_projection_digest}，其中最后摘要覆盖端点/页/成员选择；miss key 使用独立 share:miss:v1:{运行租户}:{token_sha256} 命名空间并受固定容量与来源新增预算约束，不能与有效链接缓存共用回填逻辑。
- key 的全部维度来自服务端已验证记录；不把原 token、密码、PII、任意客户端字段放 key。旧版本回填只能进入旧 key，不得覆盖新版本；命中内容仍需当前授权，连 304/条件请求也不能绕门禁。
- 前置丢弃非 43 字符 Base64URL token；主库用哈希索引查询。有效 token 才建立逐链接限流 key，随机 miss 不无限建立 Redis key；可用短 TTL（建议 ≤5 秒）、固定容量的负缓存并限制每来源新增 key 数，满时绕过缓存但仍受入口总预算，不能延长 miss 存活。Bloom filter 只作后续优化，不能作唯一授权依据。
- 授权事实读主库而非可能滞后的只读副本；Redis 无法提供可靠限流时拒绝匿名服务，不借快照缓存无限放行。限流依赖与 DB 故障均告警，返回不携带 token/底层错误。
- 保护响应统一 private, no-store；CDN/service worker 禁止缓存带 token 内容，错误、verify 与询价响应同样 no-store；静态壳可缓存但不能内嵌客户价或完整 token。

| 层/动作 | 建议预算与键 | 说明 |
|---|---|---|
| 反代/网关入口 | 每来源 IP 的请求/并发/正文预算 + 整体服务预算，数值配置化压测确定 | 在访问 DB 和 bcrypt 前挡扫描；限制 URI 长度、body 字节与新 key 速率，不仅限制单 token。 |
| 内容 API | 每有效 link + 隐私化 IP：60/min，列表与详情共用；另设每 link 总并发/预算 | 保留任务卡数值；额外全 link 预算防分布式爬取，超额不能修改永久 max_views。 |
| verify | 每 IP：10/min，另有 link+IP 的失败预算和每 link 总 CPU 并发上限 | 06 的“某链接错 5 次锁整链 15 分钟”允许攻击者锁死客户；建议改为该 link+IP/浏览会话失败 5 次冷却 15 分钟，跨来源总预算只限速/告警，需批准该语义调整。 |
| inquiry | 每 IP：3/min，再叠加 link/浏览授权/租户写入预算 | 同 IP 多 token 不能绕；同 token 多 IP 也受总预算，幂等重试不重复通知。 |

IP 取可信连接或已配置的受信代理链。现有 engine.go:43 的 SetTrustedProxies(nil) 不信转发头是安全默认，但生产反代下所有请求可能被算成代理 IP；只放行明确代理网段，不能为了“取真 IP”信任任意 X-Forwarded-For。共享 NAT 用分层预算降低误伤，实际阈值需正常客户与扫描混合负载验证。

建议把 max_views 定义为成功根页面准入数，verify 不计、失败不计；返回短期且不可伪造的浏览准入凭据，详情/询价验证此凭据与当前链接状态，不新扣页面数。浏览凭据只允许本链接选定商品，不延长链接有效期；次数耗尽后不能创建新的浏览授权，已准入会话在短期窗口内可加载详情。直接访问详情无凭据必须先完成一次准入；不能“首页计数、详情裸奔”。访问记录与计数同事务，遥测去重或 IP 去重不改变计数；响应丢失后的重试规则需在 OpenAPI 明示，不能把 max_views 说成独立访客数。

### Q5 询价与留资

现状依据：PRD §5/REQ-SHR-008；ADR-019 的加密、全掩码、近期重认证及逐次审计原则；internal/modules/order/pii.go:41、identity/auth_reauth.go:127 和 kernel/crypto/keyring.go:62。复用既有 Sealer/RequireRecent 的能力，不复用订单地址实体或照抄其 AAD。

| A 持链留资 + 分层防刷 + 全路径 PII | 有效浏览授权、Origin/请求约束、速率/内容/幂等门禁；后台掩码，披露需专权/范围/重认证/审计。 | 符合免客户账号，复用 M5c 安全能力，无新通道依赖。 | 联系方式只是自报，不能证明客户身份；需销售核实。 | customer/inquiry 信封与掩码迁移、匿名幂等、站内待办、披露与清理。 | 5–8 | 推荐。 |

| C 仅销售代录线索 | 匿名仅看，联系销售后由后台录入并加密。 | 公开写入面最小。 | 不满足 REQ-SHR-008 与 M6 完成标志，漏掉自主留资。 | 停用匿名 inquiry、修改产品验收，仍需后台 PII 保护。 | 2–3 | 仅人明确降范围才可选。 |

推荐 A 需要同时处理：

- 字段：customer 的客户/公司名、联系人、电话、邮箱；inquiry 的姓名、电话、邮箱、公司（现表没有独立公司列，不把它偷偷塞 ext）；自由留言与 item note 可能含 PII，应作为受保护文本信封。结构化 items 仅保留批准的 SPU/SKU/qty 引用；customer.tags/ext 不得成为明文旁路。
- 信封：每字段独立 nonce、cipher、key_version 与数据 revision；AAD 做领域隔离并绑定 tenant/实体类型/记录 ID/字段/revision，防跨 customer/inquiry/order 调包。记录 ID 在事务中分配，未加密前不能提交明文；密钥不可用则拒绝写入，不留“临时明文”。
- 查询：默认安全别名/全掩码 + ID/等级/归属/状态；电话/邮箱/地址不检索。真实姓名/公司也属于本次保护范围，因此原 name_trgm 索引及明文模糊搜索不能直接保留；可按独立非 PII 客户代号筛选。需要公司明文搜索或去重时另批独立契约，不把普通 SHA-256(phone) 当匿名化。
- 提交：只从 token 取 tenant/customer/link，owner 由服务器路由到当前客户归属销售或租户指定待办池；不收信任客户端传入的 owner/status/customer_id。逐项校验意向商品属于该分享、qty 正整数且有上限，留言 ≤2000 字，另限制总字节、联系方式长度与 items 数量。
- 防刷：消费与浏览会话绑定的服务端挑战/nonce，配合最小表单完成时间、隐藏陷阱及预算；这些只增加机器成本，不当身份凭证。明确同源部署或来源 allowlist，Cookie 写请求校验 Origin/CSRF，CORS 不是鉴权；不向未经验证的电话/邮箱发送自动消息，也不根据自报联系方式覆盖已有 customer。
- 幂等：作用域绑定 tenant/link/安全代次/匿名浏览授权/方法/路由/Idempotency-Key；请求摘要覆盖规范化字段与商品集合，用带密钥域隔离摘要保护低熵联系方式，持久结果仅为安全提交回执。相同键不同内容 409/10006；重放仍校验当前授权，不复用 userID=1 或跳过权限初始化。
- 可见性：归属销售及获授管理范围的主管看掩码待办；完整联系信息采用拟增三段权限 crm:pii:read + 当前 owner/dept scope + 当前管理会话严格小于 5 分钟重认证，每次披露先持久审计。审计只记录 who/记录 ID/字段集合/用途/时间/结果，不存明密文；失败不返回任何部分明文。此处是能力复用，不把 trade:order:pii:read 授给 CRM。
- 提醒：inquiry + 幂等结果 + outbox 同事务；站内通知仅含 inquiry_id、固定提示和后台入口，不含姓名/公司/电话/留言或分享 token。重试不产生多条通知，归属移交/无人负责有待办与告警，不无限发邮件。
- 转化：new → contacted → quoted → won/lost 由当前可管理销售操作；匿名者不能更新状态、查询联系人或读取历史。留资标“自报/未验证”，人工确认后再关联/新建客户，不能因持有绑定客户的链接就声称此人是该客户。
- 导出：本期匿名无下载；后台也不提供客户/询价 PII 批量导出。已有订单/商品导出权限、白名单和下载协议不扩张，crm:pii:read 不等于 export；若业务另需 PII 导出，应单独裁决用途/权限/范围/期限，沿用已有导出机制而非另做快照下载口。

| 数据 | 建议保留策略（待人确认，不能写成既有规定） |
|---|---|
| 未转化 inquiry 及其联系/自由文本 | 自提交起 180 天清理 PII；若需延长，明确目的、批准人和新期限，普通编辑/垃圾提交不自动续期。 |
| 已转化 inquiry | 必要资料确认进入受保护 customer 后，询价原始 PII 30 天内清理；只保留无 PII 的转化、商品与报价引用。 |
| customer 联系资料 | 合作期按年复核最小必要性；终止/停用后 180 天清理联系 PII，保留必要去标识业务关联。 |
| 缓存/通知/幂等/错误/审计 | 不保存联系明文或可恢复 token；披露响应 no-store。审计沿 PRD 3 年但只存安全元数据，不借审计保留期延长 PII。 |
| 备份与清理例外 | 明确备份轮换期限及恢复后重放清理标记；软删不算清理，信封仍可解密也不算匿名。受控保留需审批且限访问，不宣称立刻抹除所有离线备份。 |

上线前告知收集目的、接收角色、保存期限与联系/删除渠道；这些是实际产品契约，不以“已加密”代替留资治理。是否公开真实 customer_name、是否新增 inquiry.company 都要显式决定。

### Q6 访问统计、撤销与审计

现状依据：REQ-SHR-007 与模型 share_visit 明定 90 天；PRD §5 审计 3 年；share_visit 当前没有逐品 ID/访客身份/停留字段或上报接口。无此字段就不能声称已经知道“某客户看过哪些商品”。

| 方案 | 做法 | 优点 | 缺点 | 影响面 | 工作量 | 推荐 |
|---|---|---|---|---|---|---|
| A 仅链接汇总 | 只保留准入数/按日汇总，不留可关联的逐次 IP/UA/来源。 | 隐私面最小，存储便宜。 | 不满足既有逐次访问日志验收，排查异常能力弱；需人批准降范围。 | share_visit 简化、聚合/计数查询、验收修订。 | 1–2 | 可作为更低收集替代。 |
| B 最小化逐次访问 | 记录时间/链接/内容版本、短周期隐私化 IP、粗 UA/来源类别；90 天清理，默认不建跨链接访客画像。 | 满足现有日志目标，保留定位问题证据且降低关联风险。 | 仍可间接识别人，需要范围控制、告知和清理；逐品分析另批。 | visit 安全字段/索引/清理、统计权限、审计与监控。 | 2–4 | 推荐本期。 |
| C 经同意的实名逐品分析 | 接 Q1-C 的经验证会话，增加 item_view 事件、披露版本及专门访问权限。 | 可支持销售跟进和细粒度漏斗。 | 真实身份/行为合并风险大，需身份验证、同意与撤回链路，超出七表当前能力。 | 接收人、事件载体、逐品查询、告知/撤回、保留策略。 | 6–9 | 只有明确业务用途再追加。 |

推荐 B 的字段与用途：

- 持久字段：tenant_id、share_link_id、created_at（服务端 UTC）、披露的 snapshot checksum/内容版本、ip_hash、经归一化且截断的浏览器族/主版本及来源类别。内容版本是拟增证据；不保存原 token/hash、完整 IP、完整 UA、完整 Referer、query、指纹或精确地理位置。
- ip_hash 建议 HMAC-SHA256(独立隐私密钥，tenant + UTC 日窗口 + 规范化 IP)，输出 64 位十六进制；用于同日粗去重与异常定位，不声称匿名化。密钥与 token/加密密钥用途隔离、按窗口管理；若保留原 SHA256(ip+salt)，salt 也须服务端保密、租户/窗口隔离，公开/固定盐抵挡不了 IP 字典。
- UA 仅保留粗类别；Referer 转允许的来源类别，不保留 path/query（其中可能有别人的 token/PII）。country/city 默认不采，不为此新增 GeoIP 依赖。停留时长默认不采，当前也没有上报端点。
- 本期只说明“分配给该客户的链接被访问”，不说明“该客户本人已读/该联系人看了某 SKU”。根页面返回了商品也不证明逐个阅读；若要逐品事件，需增 SPU/SKU + event_kind + 受限会话、独立告知与权限，纳入 C 再批准。
- view_count 是准入限额的事务事实，share_visit 是访问证据，统计去重是第三种口径；三者不能混用。成功准入计数与最小访问记录同事务；写入失败不算成功，不靠“异步尽量记日志”满足访问可追溯。失败扫描只进有界安全计数/短期安全事件，不能用随机 token 把 90 天日志灌满。

撤销不重置历史保留时间：share_visit 自各自 created_at 起满 90 天删除，已撤销/过期链接同样执行，清理索引建议 tenant_id + created_at + id；清理任务有水位、失败告警和计数对账。保留必要链接墓碑防止错误复活，但不延长访问明细；审计 3 年仅保存生成/撤销/改密/重签/披露/清理等安全元数据，严禁复制 90 天访问明细进入三年审计绕过期限。

可见性建议：访问明细使用拟增 share:visit:list，而非仅凭 share:link:read；查询还必须限定 tenant、当前客户 owner/部门范围、被允许管理的链接，非客户链接按当前可管理 creator 范围。普通 sales 只见自己范围内的去标识记录/汇总；主管需明确部门授权，超管也不跳数据范围。查看将客户关联到行为的明细建议再要求近期重认证并逐次审计，普通列表不返回稳定 ip_hash；不开放匿名统计、CRM 联系方式联表导出或跨客户浏览画像。

审计分清行为主体：管理动作是 user；留资接收/访问记录由受限服务写入，现有 audit.Event 只接受 user/system/api_client，不能捏造“匿名客户=user”。如需入 audit_log，使用 system + 安全 link/inquiry 引用描述接收事件；真实管理人查 PII/统计则记其 user 与用途。审计不记原 IP/UA、token、密码、联系明文/密文或完整 payload；撤销与审计同事务，审计失败不声称撤销完成。

## 4. 未来 2 个里程碑的坑（只列不展开）

- M7（凭据自动刷新）：上游恢复同步后内容/库存会变化，不能穿透已发 snapshot，也不能使 live 偷偷扩大商品成员集。
- M7：凭据刷新失败导致 live 新鲜度下降时要能标记数据更新时间，不能把陈旧库存宣传成实时可售。
- M7：客户询价通知不能绕过既有 outbox 重试/限额，和凭据告警共用渠道时尤其需防通知风暴。
- M8（开放网关）：HMAC 外部应用能力不等于分享 token，禁止互相换取后台、CRM PII、访问统计或任意商品读取权限。
- M8：网关代理路由不得把 /share、/admin、导出预签名地址或系统探针包装成免鉴权通用转发口。
- M8：网关调用日志/上游诊断不得重新采集分享 token、联系人明文或带路径的 Referer，且不得用共享缓存打破 M6 的客户边界。

## 7. 对外暴露面清单

### 7.1 匿名可达路由与副作用

“匿名”指没有管理端 JWT；持链、密码或浏览凭据仍是授权条件。M6 API 尚未实现，下表是待批准的发布清单，响应未知处按最小建议列出，不冒充现有契约；禁止隐含增加下单、客户查询、访问统计或批量下载端点。

| 方法/入口 | 匿名准入与副作用 | 返回字段/头；泄露后果 |
|---|---|---|
| GET /s/{token} | 06 §2/3 指定 H5 入口，服务归属/静态壳交付仍需确定；页面载入后由根 API 准入，不 SSR 再重复计数。 | HTML/固定 JS/CSS 壳；不得内嵌未授权报价、联系人、token 日志或第三方埋点。HTML 若带客户数据，其风险与下表内容 API 相同。 |
| GET /api/v1/share/{token} | 校验链接/客户/报价状态、密码/浏览授权；成功准入原子扣一次 max_views、记 visit。 | 统一响应壳 + 7.2 元信息/商品清单，必要的短期浏览 Cookie；客户价/产品集合/商业条款泄露均属于商务信息泄露。密码未过只给错误与门禁提示。 |
| POST /api/v1/share/{token}/verify | token 及父引用有效，受预算限制，验证密码；不扣页面次数，不返回客户内容。 | 建议 data 仅 verified=true，Set-Cookie 签入有效期/作用域；Cookie 被盗可在期限内冒用，应如 token 保护。失败仅安全错误，无密码/hash/尝试次数。 |
| GET /api/v1/share/{token}/items/{spu_id} | 当前链接有效 + 有效浏览准入凭据 + SPU/SKU 属冻结集合，重新过门禁；记明示的访问证据，不扩成员。 | 仅该链接已授权的 7.2 商品字段；不能返回该 SPU 全部 SKU、其他报价、平台 listing 或 catalog 管理 DTO。内部商品 ID 可被猜，但非成员必须拒绝且不泄露存在性。 |
| POST /api/v1/share/{token}/inquiry | 有效链接/浏览准入、allow_inquiry、来源/CSRF、频率/体积/幂等/成员校验；写 inquiry + 安全待办。 | 建议 201 + submitted=true；不回显联系人/留言/完整 inquiry 对象或可枚举线索 ID，不提供匿名回查。防止留资接口变成信息反查与通知放大器。 |
| OPTIONS 上述路径 | 当前全局 CORS 可预检，预检不披露、不计访问、不触发业务写入；受入口总预算。 | CORS 方法/允许头等；暴露能力形状但不能授权内容。客户域建议同源；跨源必须明确 allowlist/凭据策略，不把 * 当保密控制。 |
| 经批准的图片/CDN 与静态资源 URL | 浏览器会另行请求；路径由配置/发布物确定，不虚构固定媒体 API。 | 图片本身、URL 路径/对象标识；可能泄露供应商来源、暂存签名参数并向第三方暴露访客 IP/UA。只选批准的稳定媒体，不带管理下载签名、token、客户 ID；已公开资源不能宣称随链接撤销立即收回。 |

四个 JSON API 的成功、错误、重定向及 Cookie 响应均须 private, no-store；页面加 no-referrer、受限资源策略、禁止被不受信页面嵌入和内容类型嗅探。跳转地址由受信配置生成，禁止根据任意 Host/next 参数跳向外站。二维码只是前端编码同一 URL，没有独立后端免鉴权通道。

### 7.2 字段级清单与泄露后果

“现有示例”来自 06 §5/7；建议增减均需 D2 批准，并在 OpenAPI 枚举每个嵌套键。内部证据字段不因写入 share_snapshot 就自动成为公开字段。

| 字段（适用根 API/详情） | 发布建议 | 泄露后果与边界 |
|---|---|---|
| code | 保留已有通用/70xxx 码 | 暴露处理结果；不通过详细业务数据放大链接存在性探测。 |
| message | 固定安全文案 | 反射输入可能泄露 token、PII 或上游细节；不拼原值/SQL。 |
| data | 按下列白名单；失败为空 | 直接序列化领域对象会带出成本、内部关联、联系资料。 |
| trace_id | 服务端追踪 ID | 可关联一次请求；只能查内部受权日志，不构成查询凭据。 |
| request_id（可选） | 受长度/字符约束的请求关联值 | 不信客户端当身份，不回显任意敏感长串，也不将 token 放此字段。 |
| schema_version（拟明确公开） | 固定 DTO 版本 | 暴露协议版本，便于客户端兼容，不包含内部 schema/数据库版本。 |
| generated_at（snapshot） | 冻结生成 UTC 时间 | 暴露报价形成时间/营业节奏，不等于当前库存更新时间。 |
| mode（拟补） | snapshot/live | 暴露数据性质，帮助客户判断承诺；不能只靠前端猜模式。 |
| price_basis / as_of（拟补） | 固定“正式报价/实时参考”语义及数据时间 | 表达时效，不暴露内部定价层级或组成员；必须与实际读取时点一致。 |
| content_version（拟补） | 不透明内容版本 | 可关联同次报价，不能编码客户/报价单 ID；仅版本号不是完整旧价证据，也不是绕门禁能力。 |
| price_observation（live 拟补） | 只签入本次已公开价格/商品引用/币种/版本/时间，作用域在服务端绑定 | 持有者可证明服务端曾返回该价格，但不能证明本人阅读或享有保价；不含内部客户/链接 ID，不能用作访问/下单授权。 |
| title / link.title | 选定一种响应层次，仅公开标题 | 自由文本可泄露客户名或内部项目；发布前预览，按文本呈现。 |
| customer_name / link.customer_name | 默认移除，若需展示用批准的非 PII 别名 | 转发即可暴露客户身份、采购关系，公司名也可能构成 PII；不能从 customer 表自动复制。 |
| valid_until / link.valid_until | 冻结或当前明确的有效期，RFC3339 UTC | 暴露商业报价期限；不得和链接/报价实际门禁矛盾。 |
| currency / link.currency | 单一币种 | 暴露交易币种；缺失可能误读价格，不做跨币种混合。 |
| link.note | 仅经批准的对外交易条款 | 可能泄露运费/税/折扣政策或 PII；禁止直接取内部备注。 |
| require_password | 仅门禁提示/获授权内容内状态 | 暴露保护方式；未经验证不能附带客户/商品元数据。 |
| allow_inquiry | 授权后返回布尔值 | 暴露功能开关；服务端仍检查，不能只隐藏按钮。 |
| items | 只含冻结成员的有界列表 | 产品组合本身揭示采购意向；不得自动展开新增 SKU/其他客户选品。 |
| items[].spu_id | 现契约保留，严格成员校验 | 顺序 ID 可辅助枚举；ID 不是访问权，错误不能泄露其他 SPU 是否存在。 |
| items[].sku_id | 同上，仅所选 SKU | 可推测规格/数量；绝不返回同 SPU 未授权 SKU。 |
| items[].title | 经批准商品名 | 泄露选品与未发布商品信息，标题可含敏感文本。 |
| items[].sku_title | 经批准规格名 | 泄露选定规格，不能把供应商编码混入外显规格。 |
| items[].images[] | 稳定批准 URL，有界数量 | 商品素材、原站/供应商及临时密钥可能泄露；URL 白名单、无秘密 query、避免外站跟踪。 |
| items[].description | 文本或明确受限格式 | 可能 XSS、外链跟踪及复制平台内部说明；内容审查/安全呈现，不能信任“来自 catalog 就安全”。 |
| items[].attributes | 每个键与值类型都须白名单 | 任意嵌套 JSON 可夹成本、精确库存、供应商与联系方式；未批准键拒绝/剔除。 |
| items[].display_price_cents | 最终价或未报价时空值；int64 | 客户专属商务价格泄露；不从客户端输入取值。 |
| items[].show_price（需补契约） | 明确布尔，与空价格一致 | 区分询价/零元；错误表达可造成免费或错误成交承诺。 |
| items[].original_price_cents | 默认移除，明确宣传用途才公开 | 暴露参考售价与谈判空间，不能返回成本或平台多店价区间。 |
| items[].moq | 正整数、显式起订条件 | 暴露交易条件；询价数量不足不能自动套其他低门槛价格。 |
| items[].stock_display | 只允许不显示/充足/紧张/缺货 | 仍透露粗库存和更新滞后，不等于可售承诺；禁止精确数字或可逆编码。 |
| items[].note | 仅公开行条款 | 可能泄露折扣审批、内部联系或 PII；不复用内部 price_list_item.note 而不审核。 |
| verified / submitted（拟定最小回执） | 分别只在 verify/inquiry 返回 | 仅证明本次处理成功，绝不证明联系人实名或暴露持久线索记录。 |
| Set-Cookie: share_access / 浏览准入 Cookie | 只由成功门禁签发，不在 JSON 镜像 | 泄露可在受限时限内冒用浏览；Secure/HttpOnly/SameSite/作用域与每次持久状态校验缺一不可。 |
| Cache-Control / Referrer-Policy / Retry-After（限流时） | 固定缓存/引用策略，限流只给安全重试时间 | 错误缓存策略导致跨客户复用；重试信息不包含剩余访问数、密码失败计数或内部 key。 |

全部匿名返回禁止：tenant/customer/owner/price_list 的内部 ID 与完整来源链、token/token_hash/token_prefix、password/hash、联系方式/公司原值、inquiry 内容、成本/精确库存、内部备注、供应商、shop/platform/external ID、raw/ext/_ingestion、权限/审计/访问统计以及后台导出签名 URL。token_prefix 仅后台辅助识别；公开二维码/HTML 需要的 token 只来自原 URL，不另发秘密查询接口。

### 7.3 同一后端监听端口的既存匿名入口

以下是静态路由核对，不是本轮新增端点。只发布 /s 与 /share 的反代不应顺带暴露整个监听端口；现有登录服务需要独立受控管理入口，内部探针应保持内网。

| 当前入口与证据 | 返回字段/内容 | 泄露后果；M6 发布边界 |
|---|---|---|
| POST /api/v1/auth/login；identity/auth_http.go:15 | 成功可返回 access_token、refresh_token、token_type、expires_in、user.id/username/nickname；错误为响应壳。 | 属管理认证攻击面，受 M1 登录保护；不供客户分享页调用/换权，token 响应禁止缓存或记录。 |
| POST /api/v1/auth/refresh；同上 | 新 access_token、refresh_token、token_type、expires_in，可能有 user；需要有效 refresh 凭据。 | 虽无 access JWT 仍不是无凭据接口；保留 M1 会话族规则，不允许 share token 换管理令牌。 |
| GET /healthz；httpx/engine.go:82 | 响应壳及 data.status | 暴露进程存活；按约定只在内部探针入口。 |
| GET /readyz；httpx/engine.go:83、readiness.go | 响应壳、status、data.db/data.redis 的 ok/unavailable | 暴露依赖故障与服务拓扑；公网分享域不开放。 |
