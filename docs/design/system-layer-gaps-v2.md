# 系统层缺口复核与完善计划（v2）

- 日期：2026-11-14
- 触发：用户验收 SF-5 后提出的 7 个问题 + 全量复核
- 基线：后端 `f33851e`、前端 `ef41f1c`（tag `v0.SF-5`）

## 1. 结论

系统层「功能覆盖」已齐，但**租户可用性链路是断的**，另有 3 处体验缺陷。
根因有两个设计错误，不是遗漏细节。

| # | 问题 | 性质 | 严重度 |
|---|---|---|---|
| A | 租户开通后无管理员，且邀请链接只显示一次、无法重发 | **设计缺陷** | P0 |
| B | 登录用数字 `tenant_id`，`tenant.code` 形同虚设；前端写死平台租户 | **设计缺陷** | P0 |
| C | 无「首用户自动超管」与自助注册开关 | 功能缺失 | P1 |
| D | 个人资料前端不可见、会话页缺失（后端已有） | 前端缺失 | P1 |
| E | 登出后不跳转、无真实首页、无 404 页 | 前端缺陷 | P1 |
| F | 租户列表不显示 id（含登录需要 id 的连带问题） | 前端 + B | P1 |

## 2. 逐条分析

### A. 新租户为什么「没有管理员」

现状：`POST /admin/tenants` 会创建管理员用户（`is_super=true`，`status=disabled`）+ 一个
7 天单次邀请令牌，并**只在响应里返回一次** `invite_url`。

三条断链：

1. 链接关闭即消失，没有「重新生成」入口
2. 平台管理员无法进入他人租户创建用户（跨租户 404，这是 B 的正确行为）
3. 邀请若过期/丢失，该租户**永久无管理员**，只能改库

**方案**

```
新增（平台管理员）：
POST /admin/tenants/{id}/admin-invite    重新签发管理员邀请（旧令牌作废）
GET  /admin/tenants/{id}/members         该租户用户列表（只读，供确认状态）

规则：
- 仅平台管理员可调用
- 若租户已有 active 的超管，默认拒绝（409），加 ?force=true 才重置
- 每次签发写审计（actor_tenant / target_tenant）
```

### B. 登录标识：`tenant_id` 是错的

现状：

```jsonc
POST /auth/login { "tenant_id": 1, "account": "admin", "password": "..." }
```

问题：

1. **数字 id 可枚举**：攻击者可遍历 1..N 尝试登录，配合弱口令直接命中
2. **`tenant.code` 无用途**：建了唯一 code，登录却不用
3. **前端写死** `VITE_PLATFORM_TENANT_ID=1`：任何非平台租户的用户**在 UI 上无法登录**
4. 租户列表不显示 id（前端问题），但即使显示，让用户手输数字也不合理

**方案**

```
登录改为 tenant code（字符串）：
POST /auth/login { "tenant": "acme", "account": "admin", "password": "..." }

三种取值顺序（兼容期）：
1. 显式 `tenant`（code）→ 精确匹配
2. 未传 → 使用配置 `tenant.default_code`（默认 default）
3. 子域名/自定义域（P2，后续）

`tenant_id` 数字参数废弃，保留一个版本并返回警告，下一个版本移除。

前端：登录页增加「企业代码」输入（可记住上次输入，存 localStorage 仅 code）；
平台管理员登录时填平台租户 code。
```

**限流**：失败计数按 `(tenant_code, account)` 维度，并对同一 code 的失败做租户级限速，
避免「换账号刷同一个租户」。

### C. 首用户与自助注册

```
租户设置（tenant.settings）：
  allow_self_registration  bool  默认 false

自助注册（仅当开关为 true）：
POST /auth/register { tenant, account, password, email }
  → 若租户内无 active 超管：注册者自动成为超管（且需邮箱验证）
  → 否则按租户默认角色授予（default_role_code 设置，缺省只读角色）

防护：
- 邮箱验证令牌（复用 auth_token，purpose=verify）
- 每租户每小时上限（配置项）
- 关闭时注册接口返回 403/20111
```

> 不建议默认开启。开启后必须同时具备：邮箱验证、限流、默认最小权限。

### D. 个人资料与会话

后端**已具备**：

```
GET  /auth/me            当前用户信息（含昵称/邮箱/头像/部门/角色）
PUT  /auth/profile       修改昵称/邮箱/头像
GET  /auth/sessions      我的会话
POST /auth/logout-all    全部下线
PUT  /auth/password      改密
```

缺的是**前端页面**（vben 自带 profile 页被裁剪后未接后端）。

### E. 前端体验

| 问题 | 现状 | 方案 |
|---|---|---|
| 登出 | 清 token 但不跳转/刷新 | 登出后 `location.replace('/auth/login')` 并清空 store |
| 首页 | `/home` 自动重定向到第一个菜单，无权限用户 404 | 建真实首页（欢迎/常用入口/空态） |
| 404 | 无独立页 | 增加 404 路由与页面 |

### F. 租户列表显示

- 增加 `ID` 列（平台管理员排查需要）
- 增加「管理员状态」列（未激活/已激活），直接回答「这个租户能不能用」

## 5. 验收口径（本轮）

1. 平台管理员能为任意租户重新签发管理员邀请，链接可用，完成后该租户有 active 超管
2. 新租户管理员可凭「企业代码 + 账号」在 UI 登录，无需知道数字 id
3. 已有租户（default）用 code 登录不受影响；旧的 `tenant_id` 传参在兼容期内仍可用并有警告
4. 租户列表显示 ID 与管理员状态
5. 个人资料可查看、可修改昵称与邮箱
6. 登出后回到登录页；无权限用户登录后看到首页而非 404
8. 自助注册默认关闭；开启后新用户按规则落角色并需邮箱验证
