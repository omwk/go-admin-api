## 2. 关键设计决定（不要轻易改）

| 决定 | 原因 |
|---|---|
| 登录用 `tenant` code，不用数字 id | 数字 id 可枚举；code 是唯一且可读 |
| 未知租户与密码错误返回**同一**文案 | 防租户枚举 |
| 停用租户在**密码校验之后**判定 | 否则 20111 可用来探测租户是否存在 |
| 登录失败计数按 `(tenant, account)` | 否则换账号就绕过锁定 |
| 邀请/重置令牌只存哈希、单次、7 天/30 分钟 | 明文令牌落库等于长期后门 |
| 匿名找回在 prod **不返回**链接 | 否则任何人都能重置已知账号 |
| 匿名注册对已存在账号返回**同一 202** | 防账号枚举 |
| 首用户自动超管 + 授予 `super_admin` 角色 | 只设 `is_super` 会导致菜单/数据范围失效（BE-IDN-006） |
| 收件箱对超管跳过店铺过滤 | 收件箱已按 `target=user:<id>` 隔离，再套店铺范围会误拒 |
| 平台管理员 = 平台租户内的超管 | 跨租户管理唯一入口；平台租户禁止停用（防死锁） |
| 字典分 `system` / `business` | system 随框架升级，business 归租户维护，升级不覆盖 label |

## 3. 升级流程（已有环境）

```
1. go run ./cmd/cli migrate up          # 迁移到最新版本
2. go run ./cmd/cli seed                # 补权限码与菜单；密码不重置
                                        # 会自动递增授权版本，无需手工清缓存
3. 重启 api / worker
```

注意：

- `seed` 会为**内置超管角色**补齐新增权限与菜单，其他角色授权不变
- 新权限对**非超管角色**不会自动授予，需要管理员在角色页勾选
- 升级后 `system:notify:manage` 等新权限需要按需补授

## 5. 已知限制（不是 bug，是边界）

| 项 | 说明 |
|---|---|
| 租户无删除接口 | 停用即归档；数据保留 |
| 文件管理只有上传/下载 | 列表、删除、存储抽象待业务层需要时做 |
| MFA / SSO | 首版不做 |
| 会话 IP/UA | 旧会话（升级前）无该字段，返回 null |
| 自助注册默认关闭 | 每个租户单独开启；开启需邮箱验证 + 每小时限额 |
| 平台租户不可停用 | 防「停用后无人能再启用」的死锁 |

## 6. 本轮修复过的真实缺陷

| 编号 | 缺陷 | 教训 |
|---|---|---|
| BE-IDN-004 | 无 | — |
| BE-IDN-006 | 无角色超管被数据范围拒绝（收件箱 20108、菜单为空） | 「不影响本卡」的验收附注往往是下一个 P0 |
| S1c | 可创建第二个根部门且无法删除 | 给了开关必须同时给约束 |
| FOLLOWUP-SEED | seed 后权限缓存不失效，菜单看似没更新 | 写库绕过缓存版本 = 升级静默失败 |
| BE-4 | 未映射错误返回空 body + error_code 0 | 空响应等于没有错误处理 |
