# API 网关域名策略（是否要做子域名）

- 日期：2026-11-24
- **更新（同日）**：用户决定**移除「随时添加域名」需求**，只保留单一固定 API 域名。
  本文 §2 方案 B/C 与 §3 仅作为历史评估保留，不再实施。
- 触发：用户提问「网页是 a.com，API 是否用 api.a.com，随时可添加 API 域名会不会大量复杂化」
- 结论：**单一固定子域简单；「随时添加任意域名」才复杂**。建议分三段走，现在只做第一段。

---

## 1. 现状

网关目前是**路径式**：`https://<任意域名>/open/v1/usage`。

- 签名（v1/v2）覆盖 method、path、query、body、时间戳、nonce，**不包含 Host**
- 服务本身不关心请求打到哪个域名
- 前端页面与 OpenAPI 同域部署

## 2. 三种方案与成本

### 方案 A：单一固定子域（推荐先做）

```
网页 a.com         → 管理端
API  api.a.com     → 网关
```

需要做：

| 项 | 工作量 |
|---|---|
| DNS：`api` A/CNAME 记录 | 5 分钟 |
| 证书：`api.a.com` 一张 | 5 分钟（或用现有泛域名） |
| 反向代理：`api.a.com` → 同后端 | 10 分钟 |
| 代码改动 | **0** |

> 唯一要注意：如果前端也要调 `api.a.com`，需要把新域名加进 CORS 允许列表（配置项，非代码）。

**总成本：半天运维配置，零业务代码。**

### 方案 B：泛子域 + 域名表（有第二个域名需求时再做）

```
*.a.com  → 网关（一张泛域名证书）
```

需要做：

| 项 | 工作量 |
|---|---|
| 泛域名证书（DNS-01 自动续期） | 0.5 天 |
| `gateway_domain` 表：host、租户、状态、备注 | 0.5 天 |
| Host 解析：请求进来按 Host 找租户/客户端 | 1 天 |
| 管理端「域名管理」页面 | 1 天 |
| 审计与冲突校验（同域名不可重复绑定） | 0.5 天 |

**总成本：约 3.5 人日**，且引入证书续期这一运维负担。

### 方案 C：客户自带域名（

```
api.customer.com → 我们的网关
```

在方案 B 之上再加：

| 项 | 工作量 |
|---|---|
| 域名归属校验（DNS TXT 记录） | 1 天 |
| 按域名签发证书（ACME HTTP-01 / DNS-01） | 2 天 |
| 证书存储、续期、失败告警 | 1 天 |
| 客户删除域名后的证书清理 | 0.5 天 |

**总成本：+4.5 人日**，并且每个客户域名都是一个潜在的线上故障点（证书过期 = 客户全挂）。

## 3. 关键判断

「随时可以添加 API 域名」这句话的复杂度**不在代码，在运维**：

```
域名 → DNS → 证书 → 续期 → 告警
```

每一环都可能半夜出问题。而它的收益仅仅是「URL 好看一点」。

**当前阶段没有真实外部客户，做方案 B/C 是提前支付运维成本。**

## 4. 建议

| 阶段 | 做什么 | 触发条件 |
|---|---|---|
| 现在 | 方案 A：固定 `api.<域名>`，改反向代理与 CORS | 立即 |
| 有第二套域名时 | 方案 B：泛子域 + 域名表 | 出现「api-b.xxx」需求 |
| 有客户要求自带域名时 | 方案 C | 商务明确要求 |

### 4.1 现在唯一值得做的代码预留

把「网关基地址」变成配置项，而不是散落在文档里：

```
gateway.public_base_url = https://api.a.com
```

- 管理端「客户端」页展示调用示例时用它
- OpenAPI servers 用它
- 未来换域名只改配置

**这一条 0.2 天，能省掉以后满仓库搜域名的麻烦。**

## 5. 安全提醒

如果将来启用多域名，签名建议把 **Host** 纳入规范串，防止同一套密钥在 A 域名签的请求被重放到 B 域名。

当前单域名场景不需要，但迁移到方案 B 时要一起做。
