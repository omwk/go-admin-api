# 通知模块二次评审（2026-11-19）

> 触发：用户在真实使用中发现 5 个问题。本文逐条给出根因、责任归属与整改计划。
>
> 结论：**大部分是需求与验收口径的缺失，不是实现偷懒。** 之前的卡都按「接口」验收，
> 没有按「一个功能能走通」验收。

---

## 1. 五个已确认问题

| # | 现象 | 根因（代码/数据） | 责任 |
|---|---|---|---|
| 1 | 模板编辑器没有变量插入与说明 | `template-form.vue` 的变量列表**硬编码为凭据类** `Name/Platform/Severity/Path`；身份类模板（AppName/Link/…）显示错误提示 | 设计：卡片只写正文，没要求变量面板与说明 |
| 2 | 投递记录收件人为空 | `recordRecipient` 在**发送时**调用；pending/failed 未解析收件人时 `recipient_masked` 为空。旧记录只有 hash，不可逆 | 设计：应要求入队即生成掩码 |
| 3 | 通知偏好显示模板 code | `notification_preference.go:39` 只 `Pluck("code")`，没有名称 | 设计：修了投递列表，没要求偏好页同步 |
| 4 | 未读为 0 仍有角标 | `notification-badge.vue:30` 用了 `show-zero` | 实现缺陷（S3a 遗留，从未验证） |
| 5 | 管理员无法发布公告 | 从未有「公告/群发」需求 | 设计：S3 范围缺项 |

## 2. 顺带发现的其它问题

| # | 问题 | 影响 |
|---|---|---|
| 6 | 站内消息列表用模板 code 做筛选与摘要 | 用户看到 `identity.verify` 而不是标题 |
| 7 | 未读数不轮询，只在进入页面时刷新 | 角标长期不变 |
| 8 | 模板保存只校验部分模板族的变量 | 引用未知变量 → 发送时 `template_render_failed` |
| 9 | 无模板预览 / 测试发送入口 | 改完文案只能靠真实发送验证 |
| 10 | 偏好无「事务性邮件不可关闭」约束 | 用户可关闭验证码类邮件，导致无法登录 |
| 11 | 投递记录不能按收件人/模板名搜索 | 只能按 code 精确筛 |
| 12 | 无公告历史与撤回 | 发错无法处理 |
| 13 | 通知中心无「全部已读」以外的批量操作 | 大量未读难清理 |
| 14 | 模板 locale 只能 zh-CN，无管理入口 | 出海场景受限（暂不处理） |

## 3. 根本原因

三张卡（S3a 收件箱、S3b 渠道、BE-IDN-015/016/017）都以「接口通过测试」为验收，
缺少一次**端到端用户流程**验收：

```
管理员配置渠道 → 编辑模板（看得懂变量）→ 触发通知 →
用户收到站内信与邮件 → 偏好可调 → 失败可重试 → 公告可群发
```

任何一环没走通，接口测试全绿也没用。

## 4. 整改计划

| 卡片 | 端 | 内容 |
|---|---|---|
| BE-IDN-018 | 后端 | 偏好名称与事务性约束、模板变量声明/校验/预览/测试、入队即掩码、公告群发、站内消息标题 |
| FE-IDN-013 | 前端 | 变量插入面板与说明、预览抽屉、偏好名称、角标为 0 隐藏与轮询、通知中心标题、公告发布页 |
| 本文 §5 | 验收 | 端到端清单，必须逐条走通并截图 |

## 5. 端到端验收清单（下次交付必须全绿）

| # | 步骤 | 通过标准 |
|---|---|---|
| 1 | 管理员打开模板编辑 | 看到当前模板可用变量、含义、示例，可一键插入 |
| 2 | 保存引用未知变量的模板 | 前端拦截/后端 400，提示具体变量名 |
| 3 | 模板预览 | 显示渲染后的主题与正文（样例值） |
| 4 | 模板测试发送 | 发到配置的测试收件人，投递记录出现一条 |
| 5 | 触发注册验证 | 收到邮件；链接为绝对地址；点击可完成验证 |
| 6 | 投递记录 | 该条显示模板中文名、掩码收件人、状态、失败原因 |
| 7 | 停掉 worker 再触发 | 记录为 pending，页面出现「卡住」提示 |
| 8 | 恢复 worker 并重试 | 状态转 sent / failed，失败原因中文 |
| 9 | 偏好页 | 显示模板名称；事务性模板不可关闭且有说明 |
| 10 | 站内通知 | 通知中心显示标题与摘要；点击可标记已读 |
| 11 | 未读数 | 为 0 时角标消失；新消息 60 秒内出现 |
| 12 | 公告 | 管理员发布公告 → 目标用户收到站内信（选邮件则同时发邮件）→ 公告历史可见 |
