# S3 · 全链路冒烟脚本（M6 之后、M7 之前）

- 类型：工程任务，不属于业务里程碑
- 依赖：M6 已合并
- 预计：**0.5–1 人日**
- 分支：`chore/s3-smoke`
- 完成标志：`scripts/smoke.ps1` 在干净环境一条命令跑通全链路，失败时指出**第一处**断点。

---

## 1. 为什么现在做

M0–M6 全部交付，但**从未以「API 进程 + worker 进程 + 真实 Redis/Postgres」的组合运行过**。所有验证都是 `go test`，每个包各自建 schema、各自起 httptest。

这类问题只有真跑才会暴露：

- worker 启动时缺配置项（单测用默认值掩盖）
- 队列名/任务类型在生产者与消费者之间不一致
- 迁移在真实库上因权限或扩展缺失失败
- 定时任务没注册（cron 表达式解析失败只在启动日志里）
- 健康检查通过但业务路由 500

## 2. 脚本要覆盖的链路

| # | 步骤 | 断言 |
|---|---|---|
| 1 | 依赖就绪 | Postgres、Redis 可连接；迁移版本 = 最新且 dirty=false |
| 2 | 启动 API 与 worker | 两个进程在 N 秒内 `/readyz` 返回 ok |
| 3 | 种子与登录 | seed 创建管理员 → 登录取 access_token |
| 4 | 建店铺 | 接 mock 平台，凭据写入并解密可读 |
| 5 | 触发同步 | 商品与订单各跑一轮，run 状态 = success |
| 6 | 数据落地 | listing / product_spu / sales_order 行数与 mock 数据一致 |
| 7 | 归并 | 手工归并两个 listing 到同一 SPU，冗余列重算正确 |
| 8 | 客户与报价 | 建客户、专属价目表、一条专属价 |
| 9 | 生成分享链接 | 带密码；返回 token 与有效期 |
| 10 | 匿名访问 | 无密码 → 拒绝；验证密码 → 拿到内容；价格 = 专属价 |
| 11 | 提交询价 | 201 且 DB 中为密文 |
| 12 | 管理侧查看 | 无重认证 → 403；重认证后 → 明文可见且写审计 |
| 13 | 撤销链接 | 撤销后匿名访问立即 403 |
| 14 | 清理 | 停止进程，删除临时数据 |

## 3. 失败可定位

脚本必须满足：

- 每个步骤有独立编号与名称，失败时打印 `步骤 7 (归并) 失败：<原因>`
- 保留每一步的 HTTP 状态码与 request_id
- 失败时不继续后续步骤（避免级联噪声）
- 结束时打印汇总表：步骤 / 结果 / 耗时

## 4. 运行方式

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/smoke.ps1
  -DatabaseUrl <dsn>      默认读 .env 的 TEST_DATABASE_URL
  -RedisAddr <addr>       默认读 .env
  -KeepArtifacts          失败时保留进程日志与临时数据
```

要求：

- 使用**独立 schema/前缀**，不污染开发数据
- API 与 worker 用随机端口启动，避免端口冲突
- 超时保护：单步默认 30 秒，整体 5 分钟
- 脚本纯 ASCII（Windows PowerShell 5.1 按 ANSI 读 .ps1）
- 退出码：0 全通过；非 0 表示第一步失败

## 5. 硬性要求

- **不得跳过失败步骤继续跑**（告警会淹没真正的断点）
- **不得把断言写成「有响应就算过」**：每个 step 至少断言一个具体值
- 不得依赖人工点击或浏览器
- 不得修改产品代码来让冒烟通过；发现产品缺陷记入 `docs/proposals/backlog.md`
- 若某步因环境缺失无法执行（如对象存储未配置），必须**显式 skipped 并说明原因**，不得静默通过

## 6. 验收

| # | 项 | 断言 |
|---|---|---|
| 1 | 一条命令跑通 | 干净库上退出码 0，汇总表全绿 |
| 2 | 断点定位 | 故意改坏一步（如撤销后不生效），脚本指出正确步骤号 |
| 3 | 可重复 | 连续跑两次，第二次仍全绿（验证幂等与清理） |
| 4 | 不污染 | 跑完后开发库里没有残留 schema/租户 |
| 5 | 耗时 | 全流程 < 5 分钟 |
| 6 | 文档 | `AGENTS.md` §8 增加 `scripts/smoke.ps1` 条目 |

## 7. 已知会暴露的问题（预判，不预先修复）

- worker 与 API 的配置项差异
- mock 平台的订单资源是否需要单独注册
- 分享链接的 Cookie 路径与匿名 API 前缀是否匹配
- 询价通知是否真的落到 inbox
- 撤销后缓存是否真的失效（单测覆盖了，但没有跨进程验证过）

**这些不是预期内的失败**，是要在冒烟里确认「到底有没有」。
