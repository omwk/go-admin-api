## 1. 估算偏差

| 里程碑 | 原估（人日） | 实际（人日） | 倍数 | 真实难点 |
|---|---:|---:|---:|---|
| M0 脚手架 | 5 | 5 | 1.0 | 无边界条件 |
| M1 身份权限 | 12 | 20 | 1.7 | 多角色 scope 并集、会话族 |
| M2 店铺凭证 | 5 | 9 | 1.8 | 多版本 AEAD 密钥 |
| M3 同步框架 | 12 | 22 | 1.8 | 来源仲裁、公平调度 |
| M4 商品域 | 4 | 24 | 6.0 | 归并串价、历史重放 |
| M5 订单域 | 4 | 24 | 6.0 | PII 全路径、状态维度 |
| M6 分享报价 | 3 | 22–32 | 8–10 | 匿名边界、定价冻结 |
| M7 凭证刷新 | 2–3 | 18–28 | 7–9 | 一次性令牌、未知结果 |
| M8 开放网关 | 4 | 24–36 | 6–9 | 计量准确性、密钥生命周期 |
| M9 计费对账 | 4 | 28–42 | 7–10 | 资金一致性、1 分差异 |

### 规律

**原卡只描述正常路径，真实工作量在边界条件上。**

- M0 没有边界条件 → 估算准确
- M4 之后每个里程碑都要回答「出错了会怎样」：串价、漏单、PII 泄露、重复消费、超扣
- 这些问题的答案不在功能清单里，而在**失效模式**里

### 结论

估算应该拆成两栏：**功能路径** 与 **失效模式**。后者约占 60–80%，且随「对外暴露程度」上升：

```
纯内部（M0/M1/M2）      1.5–2 倍
内部 + 数据管道（M3/M4）  6 倍
对外暴露（M5–M9）        6–10 倍
```

## 2. 有效的实践

### 2.1 Gate A 评审（M4 起）

每个里程碑开工前先写 `docs/proposals/Mx-review.md`，产出：

- 规格冲突清单（编号，便于逐条裁决）
- 风险排序（P0/P1，含触发条件与后果）
- 每个争议点 2–3 个方案 + 推荐 + 影响面
- 待决策清单

**效果**：M6 的匿名边界、M7 的一次性令牌、M8 的计量身份、M9 的资金并发，四类致命问题都是在评审阶段被逼出来的，不是实现时发现的。

**代价**：每次 1–2 人日；但相比事后返工，这个投入回报最高。

### 2.2 任务卡 > 聊天指令

所有需求落在 `docs/milestones/*.md`，聊天里只说「做第几批」。实现者偏离的每一次，都发生在口头指令与任务卡不一致时。

### 2.3 偏差必须逐条写

PR 描述强制包含「偏差说明」，写「无」也要写。实际效果：

- M4b 的性能未达标被显式记录，成了 M9 的门禁
- M6 的 Cookie Path 偏差被记录，M6c 才能对齐
- M9c 的「配额移 Redis」冲突被拦下

### 2.4 可执行的验收

验收不是「测试通过」，而是**能复现的命令 + 数字**：

```
100 分余额 / 5 分单价 / 30 并发 → 恰好 20 次成功、余额 0
百万令牌枚举 → 0 成功，p=0.6262
```

这类断言能证伪，也能在回归时当基线。

### 2.5 工程债独立成卡（S 系列）

- **S0**：CI 分片（15 分 26 秒 → 最慢 2 分 10 秒）
- **S1**：超时预算配置化（分离交互事务与迁移 DDL）
- **S2**：测试运行时重构（bootstrap 330 → 128 秒，迁移只跑一次）
- **S3**：全链路冒烟（16 步，49 秒）
- **D1**：重放 ETA 的固定 2 秒租约

工程债不塞进业务里程碑，而是独立卡片、独立验收。

## 3. 无效或低效的实践

### 3.1 迁移测试的清单断言

每个迁移后断言「表名清单 / 外键清单 / 索引清单」。**22 个迁移、121 条断言，一次都没抓到过 bug**——它们抓到的只有「忘了同步改测试」。

S2 砍掉后，bootstrap 从 330 秒降到 128 秒，业务覆盖不变。

### 3.2 「连续 N 次 CI 全绿」作为门禁

CI 是共享（或争用中的）runner，5 次全绿不能证明第 6 次不红。正确做法：

- 本地 `-count=20` 高频重复 → 统计性验证
- CI 跑 1 次 → 环境验证
- 后续 PR 自然观测 → 长期验证

### 3.3 容量断言跑满规模

| 断言 | 本地 | CI | 结果 |
|---|---|---|---|
| 50 万成员冻结 <3s | 1.94s | 超时 | 改为默认 5 万 + `REPLAY_CAPACITY_FULL=1` |
| 10 万行导出 <3s | 0.92s | 3.39s | 改为默认 2 万 + `EXPORT_CAPACITY_FULL=1` |
| 时序侧信道 p 值 | p=0.63 | 噪声淹没 | 改为形状断言（四种失败响应一致） |

### 3.4 过度并行

自建 runner 开 3 个：core 分片从 13 分 23 秒。减到 2 个：2 分 20 秒。

**这类测试是 I/O 密集（建 schema、跑迁移），并行只增加争用。** 并行度要按任务特性定，不是越高越好。

### 3.5 把 CLI 缺失当成环境不存在

实现者两次因为「找不到 `make` / `docker` / `psql`」而停下来问。沙箱 PATH 与宿主不一致，但**测试通过 `.env` 直连数据库，根本不需要 CLI**。

已写入 `AGENTS.md`：命令找不到 ≠ 环境不存在。

## 4. 技术决策回看

### 做对了

| 决策 | 验证方式 |
|---|---|
| 三层数据模型（raw → canonical → mapping） | 32 个字段变动的重放测试 |
| 版本化 AEAD + 5 维 AAD | 篡改任一密文解密失败 |
| 权限码 3 段式 + 模块前缀校验 | reflection 矩阵 |
| 数据范围显式声明（5 种 scope） | 越权 404 矩阵 |
| 来源仲裁用 raw ID 主序 | 旧来源整组跳过 |
| 账本式钱包 + PG 条件更新 | 30 并发恰好 20 成功 |
| 独立对外 DTO | M6/M8 两次避免了内部字段外泄 |

### 走了弯路

| 决策 | 问题 | 修正 |
|---|---|---|
| 让实现者自研表达式求值器 | 550 行、`big.Rat` 触发 CVE | 换 `expr-lang` + `jsonpath` + `decimal`，Apply 快 7.7 倍 |
| 迁移编号按里程碑预分配 | 两次重排（插入 000005 导致 000006/000007 前移） | 改为「落地时最大号 +1」 |
| 对外 DTO 从内部裁剪 | M6 差点泄露成本价 | 改为独立定义 |
| 断言「50 万 <3s」进 CI | 三次 flaky | 规模开关 |

### 值得记录的两次「实现者做对了」

1. **M6c**：主动指出「审计只增」与「保留 3 年」冲突，提出受限删除通道
2. **M9c**：主动指出「配额移 Redis」与已批准评审冲突，给出 A/B 两案

这两次都是**指令与既有裁决矛盾时先停下**，而不是自行取舍。

## 5. 如果重来，三个改变

### ① Gate A 从 M1 开始

M4 才成型，前三轮靠实现者的判断。如果 M1 就有完整的评审，scope 并集语义与密钥版本设计会少返工。

### ② 全链路冒烟从 M3 开始

M6 之后才有 S3。在此之前，「API + worker + 真实 Redis + Postgres」从未一起跑过，装配错误只能靠集成测试碰运气。

### ③ 性能门禁进 ADR 模板

M8c 才发现网关 58ms。如果每个 ADR 都强制写「延迟预算」，M8 的计量设计从一开始就会考虑写合并，而不是事后优化。
