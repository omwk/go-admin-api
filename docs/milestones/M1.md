## 7. 权限码规范（ADR-011）

固定三段：`module:resource:action`，全小写，冒号分隔。

| 权限 module | 资源 | 对应 Go 包 |
|---|---|---|
| `system` | user, role, menu, permission, dept, session, setting | identity |
| `shop` | store, credential, platform | shop |
| `product` | spu, sku, category, inventory, listing | catalog |
| `trade` | order, pii | order |
| `crm` | customer, pricelist, inquiry | share |
| `share` | link, visit | share |
| `sync` | job, run, dlq, quarantine, drift, mapping, item, replay | sync |
| `gateway` | route, client, log | gateway |
| `billing` | wallet, plan, statement, reconcile | billing |

**硬性约束**：

- `sys_permission.module` 必须等于 `code` 的第一段（service 层校验 + 单测）。
- 禁止出现两段码或四段码，禁止把通配符或接口表的动作缩写当作实际权限码保存。
- 权限码集中定义在 `internal/modules/identity/permission/registry.go`，**禁止散落在 handler 字符串里**；种子、中间件、测试都从这里取。

## 9. 关键设计

### 9.1 Token 与会话（ADR-012）

- access JWT：HS256，15 分钟，claims `sub(user_id) tid(tenant_id) sid(会话ID) jti exp iat`。**不放权限码**。
- refresh：32 字节随机，`sys_refresh_token` 存 `sha256`，7 天。
- **每次登录生成新 `sid`**；同一 `sid` 内的 refresh 轮换是"一条链"。
- 多端：PC 和手机各自登录 → 不同 `sid` → 刷新互不影响。

**轮换规则**：

1. 查 token hash，未知返回 401/20103；校验 family 持久撤销状态，登出/强踢/重放后立即返回 401/20103。自然过期返回 401/20102。
2. DB 事务锁定并校验旧 token，插入同 sid 的新 token，更新旧行 `revoked_at`、`revoked_reason=rotated` 和 `replaced_by_token_id`；同 sid 的刷新与撤销操作必须串行协调。
3. DB 提交后同步写旧 refresh 失效 key，再返回新 token。DB 事务中不做 Redis IO；DB 提交后 Redis 写失败须暴露依赖故障，不返回成功。
4. 仅 `rotated` 旧 token 且 family 有效时，从首次轮换时刻起 ≤30 秒的复用返回 409/20109：不撤 family、不签发、不延长宽限；超过 30 秒再复用才撤 family 并返回 401/20103。
5. refresh endpoint 不得看到 Redis 旧 hash 标记就直接返回 20103，必须读取 DB 区分宽限与其他撤销原因。客户端等待成功的并发刷新结果，使用已下发的新 token；成功结果丢失则重新登录，不反复提交旧 token。
6. 登出/强踢/重放将该 sid 标记为持久撤销，阻止后续签发；Redis 恢复后 JWTAuth 仍拒绝已持久撤销的 session，不能只依赖易失的黑名单。

### 9.2 Redis 失效命名空间（ADR-012）

三套 key，互不复用：

| 用途 | Key | TTL |
|---|---|---|
| 单个 access token 失效 | `auth:v1:revoked:access:jti:{jti}` | access 剩余有效期（≤15m） |
| 单个 refresh 失效 | `auth:v1:revoked:refresh:sha256:{token_hash}` | refresh 剩余有效期（≤7d） |
| 整个会话失效 | `auth:v1:revoked:session:{sid}` | 该 sid 最晚 refresh 剩余（≤7d） |

- 登出 / 强制下线：写 **session** 键，同时标记可确定的目标 access jti 与当前 refresh hash；不能标记管理员自己的 token 作为目标会话。session 键覆盖该 sid 全部 access。
- 轮换：只写 **refresh** 键。
- 鉴权中间件：校验 `jti` 未撤销 **且** `sid` 未撤销。
- Redis 不可用 → **fail closed**（503/10002），明确已撤销为 401/20103，同时 `/readyz` 反映降级。TTL 按到期时间计算，≤0 时不写，重复失效不得缩短已有 session 撤销覆盖期。

### 9.3 登录安全

- 密码 bcrypt cost **12**，M1 保留；M10 登录压测记录 bcrypt 延迟/CPU 后再裁决，不提前降低。
- **锁定按用户名**：连续失败 5 次 → `locked_until = now + 15min`，返回 `20104`。
- **IP 只限流不锁定**：登录接口 10 次/分钟/IP，超限 429 `10005`；被限流请求不增加用户名失败次数。用户名锁定在同租户跨 IP 生效，不以 IP 建账号锁。
- 登录成功清零计数，记录 `last_login_at/ip`。
- 用户不存在时也做一次 bcrypt 比对，减少用户名枚举的时间差；不声称整个 HTTP 响应严格恒定时间。

### 9.4 菜单与权限（ADR-011）

- `sys_menu` 与 `sys_permission` **保持分表**：菜单管展示与路由，权限码管接口与按钮。
- **鉴权只认 `sys_permission.code`**；`sys_menu.permission_code` 仅用于前端展示与关联。
- `sys_menu.permission_code` 建复合外键；删除被引用的权限点 → `20105`。
- 菜单树规则：只返回 `status=active` 且 `visible=true`；按钮类型不入树；深度 ≤ 5；父不可见则子不可见。
- 超管（`is_super`）返回全部菜单。

### 9.5 数据权限（ADR-011）

`data_scope` 解析规则：

| scope | 条件 |
|---|---|
| `all` | 无附加条件 |
| `dept` | `dept_id = 当前用户部门` |
| `dept_and_child` | `dept_id IN (本部门及子部门)`，用 `sys_dept.path` 前缀匹配 |
| `self` | `owner_user_id = 当前用户`（表无该列则退化为 `created_by`） |
| `custom` | `dept_id IN (sys_role_dept 中该角色的部门)` |

- **显式套用**，不做 GORM 全局注入。
- repo 只使用 bootstrap 注入的 ScopedQuery 门面，内部封装 `db.Scoped(ctx, model)`，不暴露原始 GORM handle；**depguard** 禁止 repo 导入 `gorm.io/gorm`、`internal/kernel/db` 和直接 SQL 驱动。不写自研 AST。
- 按 repo 方法列 DryRun 覆盖矩阵：列表、详情、计数、更新/删除、join/alias 等查询均检查 tenant 和数据范围；覆盖 5 种 scope、缺失身份拒绝执行及跨 owner 集成测试。新增查询必须同步补矩阵，不能只测公共 Scope 函数。
- repo 只暴露查询接口；测试用 Go reflection 枚举接口方法，与 DryRun 用例登记的方法集合比较，缺项直接失败，不扫描 AST。私有查询辅助路径纳入对应接口方法的分支用例。
- 登录、refresh hash 解析、身份/授权加载与 seed 不能依赖尚未建立的用户数据 Scope：由 bootstrap 分别注入专用查询能力，按已确定的租户、已验证 token 的用户/sid 或内部 seed 租户限定；禁止接受客户端的“跳过 Scope”参数或暴露通用绕过入口。上述方法同样登记 DryRun 矩阵，业务查询缺失身份仍拒绝执行。
- **`is_super` 只跳过 RBAC，不跳过数据权限**；超管看全量是因为种子角色 `super_admin` 的 `data_scope='all'`。
  - 种子必须保证这个不变式，并写一个测试：`super_admin` 角色的 `data_scope` 被改动时测试失败。
- 超管访问视为高敏操作，写 `audit_log`。

### 9.6 缓存与生效（ADR-011）

版本化缓存，避免"删除后被并发请求写回旧值"：

```
版本键：authz:ver:{tenant}:{user}                 无 TTL
权限：  authz:perm:{tenant}:{user}:v{n}           TTL 5min
菜单：  authz:menu:{tenant}:{user}:v{n}           TTL 5min
```

- 授权变更事务提交后：解析受影响用户 → 同步 `INCR authz:ver:{tenant}:{user}`。覆盖角色权限/菜单、用户角色、角色状态/数据范围及菜单配置变化；权限和菜单共享版本。
- 读取时先取版本，再读缓存；DB 回填使用原先读取的版本。版本与缓存读取有依赖，不能合并为独立 pipeline 查询。
- 旧版本的 key 从此刻起不可达，无需逐条 DEL。
- 失效失败：记 `Warn` + 指标 `authz_invalidate_failed_total`，依赖 5 分钟 TTL 兜底。
- **M1 不做 outbox 重试**（M3 T3.11 接入）；Redis 不可用时鉴权拒绝服务，不回退旧本地权限；恢复后的遗留缓存按 5 分钟 TTL 收敛。5 秒目标适用于 Redis 正常的同步失效路径。
- 菜单 5 秒生效指服务端下一次 `/auth/menus` 返回新值；已打开页面需前端重新请求，M1 无前端改动或菜单推送。

### 9.7 中间件链

```
TraceID → Recovery → AccessLog → CORS → Timeout
  → (auth 组) JWTAuth → LoadIdentity(sid 校验) → LoadPerms(缓存) → RequirePerm("system:user:list")
  → (open 组) HMACAuth（M8）
```

- `JWTAuth`：验签 → 过期 → `jti` 未撤销 → `sid` 未撤销 → 注入 `UserIdentity`。
- `LoadIdentity`：查用户状态（停用立即拒绝，不依赖 token 过期）。
- `RequirePerm`：`is_super` 跳过 RBAC；否则权限码集合包含即可。

## 11. 验收清单

### M1a

```bash
make migrate-up && make seed
make run-api &

# 登录（PC）
curl -s -X POST localhost:8080/api/v1/auth/login -d '{"username":"admin","password":"<seed>"}'
# 再次登录（模拟手机）→ 得到不同 sid
# PC 刷新 → 手机不被踢
# 同一 refresh 立刻再用一次 → 409 / 20109
# 等 31 秒后再用 → 401 / 20103，且该 sid 全部失效
# 登出 → 该 sid 的 access 立刻 401
```

| # | 验收项 | 通过标准 |
|---|---|---|
| 1 | 登录成功/失败 | 错误密码 401/20101；5 次后 423/20104 |
| 2 | access 过期 | 401/20102 |
| 3 | 轮换 | 旧 refresh 失效，新 refresh 可用；`replaced_by_token_id` 有值 |
| 4 | **多端隔离** | PC 刷新后，手机的 refresh 仍可用 |
| 5 | **宽限期** | 轮换旧 refresh 在 0/29/30s 复用 → 409/20109，不撤 family、不签发、不重置宽限；用可控时钟验证 |
| 6 | **重放检测** | 超过 30s 复用 → 401/20103，且该 sid 所有 refresh 失效 |
| 7 | 登出 | 该 sid 的 access/refresh 立即失效，其他 sid 不受影响 |
| 8 | menus 聚合 | 一次返回 `{user, menus, permissions}`，与 `/auth/me` 一致 |
| 9 | 锁定 | 同一用户名 5 次失败后锁定；不同 IP 登录同一用户名仍被锁 |
| 10 | IP 限流 | 单 IP 1 分钟第 11 次触发 429/10005；用正确凭据验证不引入账号锁，被限流请求不增加失败计数 |
| 11 | 独立交付 | 全新库 `make migrate-up && make seed` 后登录/菜单可用；认证 OpenAPI 完整；未暴露管理 CRUD |

## 12. 评审结论（已裁决，不要再改）

Gate A 的结论已写入 ADR-011 / ADR-012 / ADR-013，此处只列摘要：

| 议题 | 结论 |
|---|---|
| 权限码层级 | 三段 `module:resource:action` |
| 数据权限 | 显式 Scope + `db.Scoped` 门面 + `depguard` 禁止 repo 直连 gorm |
| 菜单/权限 | 分表，加复合外键与 RESTRICT |
| 多端 | 每次登录一个 `sid`，刷新互不影响 |
| 并发刷新 | 30 秒宽限 + `20109`，超时才撤 family |
| 缓存失效 | 版本键 + 同步 INCR，5 分钟 TTL 兜底，outbox 推迟到 M3 |
| 超管 | 只跳过 RBAC，不跳过数据权限 |
| 登录保护 | 用户名锁定、IP 只限流；bcrypt cost 12 保留到 M10 压测裁定 |
| 分批交付 | M1a 独立验收并合并后打 `v0.M1a`，再进入 M1b |
