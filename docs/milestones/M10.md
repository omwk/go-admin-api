# M10 · 加固与交付

- 依赖：M0–M9
- 预计：4 人日
- 分支：`release/v1.0`
- 覆盖需求：全部非功能项
- 完成标志：压测达标、安全清单全绿、备份可恢复、部署文档能让第二个人独立上线。

---

## 1. 目标

从「能跑」到「敢交给别人跑」。这一阶段不加业务功能，只做稳定性、安全性、可运维性。

## 2. 范围

1. 性能压测与调优
2. 安全加固（OWASP 自查 + 渗透测试清单）
3. 可观测性（指标、日志、告警、看板）
4. 备份恢复演练
5. 密钥轮换流程
6. 部署与发布流程（含回滚）
7. 运维手册与故障预案
8. 文档收尾（OpenAPI 汇总、ERD、部署图）

## 3. 不做

- 不做 K8s 编排（除非已有集群）
- 不做多机房容灾
- 不做 SOC2 合规认证
- 不做容量自动扩缩容

## 4. 性能目标

| 场景 | 目标 |
|---|---|
| 管理端列表（10 万数据） | P95 < 500ms，P99 < 1s |
| 分享页（快照） | P95 < 100ms |
| 网关代理（不含上游） | 额外开销 < 10ms |
| 同步吞吐 | 单店铺 5 万订单/天，4 小时内完成 |
| 并发 | 200 QPS 管理端 + 50 QPS 网关，错误率 < 0.1% |
| 内存 | 稳态 RSS < 512MB |
| 长跑 | 72 小时无内存泄漏（`go tool pprof` 对比） |

**压测方法**：
- `k6` 或 `vegeta` 脚本放 `test/load/`
- 数据：造 10 万商品 / 10 万订单 / 100 万调用日志
- 记录基线，写进 `docs/performance.md`

## 5. 安全清单

| # | 项 | 检查方式 |
|---|---|---|
| 1 | 凭据/PII 加密 | 直查 DB 无明文；`strings` 二进制无密钥 |
| 2 | 日志无敏感 | 全量日志 grep token/密码/手机号规则 |
| 3 | SQL 注入 | 所有查询参数化；`sort` 白名单 |
| 4 | XSS | 分享页输出转义；富文本白名单（若展示） |
| 5 | SSRF | 网关上游地址校验 + 内网段拦截 |
| 6 | 越权 | 水平越权测试：A 用户访问 B 的资源 |
| 7 | 暴力破解 | 登录/分享密码限流 + 锁定 |
| 8 | 重放 | 网关 nonce；JWT jti 黑名单 |
| 9 | 依赖漏洞 | `govulncheck ./...` 零高危 |
| 10 | 密钥管理 | 主密钥不落代码仓库；轮换演练 |
| 11 | 传输安全 | 强制 HTTPS；HSTS；安全响应头 |
| 12 | 上传 | MIME/大小/扩展名校验；不在 web 根目录 |
| 13 | 错误泄露 | 生产环境不返回堆栈/SQL |
| 14 | 审计 | 敏感操作 100% 有记录 |

## 6. 可观测性

### 6.1 指标

- HTTP：`http_requests_total{route,method,status}`、`http_request_duration_seconds`
- 同步：见 `docs/05-platform-sync.md` §9
- 凭据：`credential_expiring_total`、`credential_refresh_failures_total`
- 网关：`gateway_calls_total{route,client,status}`、`gateway_rate_limited_total`
- 计费：`wallet_frozen_cents`、`billing_reconcile_diff_total`
- 队列：`asynq_queue_size{queue}`、`asynq_task_failed_total`
- DB：连接池使用率、慢查询数

### 6.2 看板（Grafana）

1. 总览：QPS、错误率、P95、队列积压
2. 同步：run 成功率、游标延迟、隔离/漂移数
3. 网关：调用量、限流、上游错误
4. 计费：余额分布、冻结、对账差异
5. 资源：CPU/内存/DB 连接/Redis 内存

### 6.3 告警

| 告警 | 阈值 | 级别 |
|---|---|---|
| API 错误率 | > 1% 持续 5min | P1 |
| P95 延迟 | > 1s 持续 5min | P2 |
| 同步连续失败 | 3 次 | P1 |
| 游标延迟 | > 1h | P2 |
| 凭据 needs_reauth | 任意 | P1 |
| 漂移 critical | 任意 | P2 |
| 对账差异 | > 0 | P1 |
| 队列积压 | > 1000 持续 10min | P2 |
| 磁盘 | > 80% | P2 |

## 7. 备份与恢复

- PG：每日全量 `pg_dump` + WAL 归档（或云托管自动备份），保留 14 天。
- Redis：只存缓存与队列，**不作为唯一数据源**；RDB 每日一次即可。
- 对象存储：版本化 + 生命周期。
- **恢复演练**（必须真做一次）：
  1. 新机器起 PG
  2. 恢复最近全量 + WAL 到指定时间点
  3. 启动 api，跑冒烟测试
  4. 记录 RTO/RPO，写进 `docs/runbook.md`

目标：RPO ≤ 1h，RTO ≤ 2h。

## 8. 密钥轮换

```
1. 生成新主密钥 key_version=2，加入配置（保留 v1）
2. 部署（此时新写入用 v2，旧数据仍 v1）
3. 后台任务批量重加密：解密 v1 → 加密 v2 → 更新 key_version
4. 校验：所有密文 key_version=2
5. 移除 v1
```

- 重加密任务分批（每批 200），可断点续跑，失败重试。
- 必须先在测试环境演练一遍。

## 9. 部署与发布

```bash
# 发布
git tag v1.0.0
./deploy/release.sh v1.0.0     # build → 镜像 → 迁移 → 滚动重启 api → 重启 worker
# 冒烟
./deploy/smoke.sh             # 登录/列表/分享页/网关 四个关键路径
# 回滚
./deploy/rollback.sh v0.9.0   # 镜像回退 + 迁移 down（若可逆）
```

- 迁移必须**向前兼容**（先加列后删列，分两次发布），保证回滚时旧代码能跑。
- worker 先停后启（避免任务重复），api 滚动重启。
