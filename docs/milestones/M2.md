## 1. 目标

把「店铺」和「凭据」做成两个干净的领域：凭据只进不出，版本可追溯，密钥可轮换。

## 2. 范围

1. 表：`platform / shop / shop_credential / credential_version / credential_audit`（迁移 `000003_shop_init`；`credential_refresh_run` 放 M7）
2. 信封加密工具（AES-256-GCM + key_version + AAD）
3. 平台注册表 CRUD（只读为主，种子 3 个平台）
4. 店铺 CRUD + 数据权限
5. 凭据录入/轮换/校验/停用
6. 凭据审计
7. 幂等中间件（`Idempotency-Key`）
8. 文件上传（S3/MinIO）基础能力

## 3. 不做

- 不做自动刷新调度（M7）
- 不做真实平台连通性（`Check` 先返回 `ErrUnsupported`，M3 接真实实现）
- 不做 cookie 的浏览器自动化
- 不做凭据导入导出

## 7. 关键设计

### 7.1 信封加密

```go
type Sealer interface {
    Seal(plaintext []byte, aad string) (cipher, nonce []byte, keyVersion int, err error)
    Open(cipher, nonce []byte, aad string, keyVersion int) ([]byte, error)
}
```

- 算法：AES-256-GCM，nonce 12 字节随机。
- AAD：`fmt.Sprintf("%d:%d:%s:%d", tenantID, shopID, kind, versionNo)` —— 防止密文跨店铺/跨版本调包。
- 主密钥：`crypto.master_key`（base64 32 字节），支持 `key_version` 多把（配置为 map）。
- **解密后立即用完即弃**，不缓存明文；如需在内存中传递，用 `[]byte` 并在 `defer` 中清零。
- 指纹：`sha256(plaintext)` 前 12 位 hex，用于判断「是否变化」，不可逆。

### 7.2 凭据版本

- 首次录入：`version_no=1`，`shop_credential.current_version_id` 指向它。
- 轮换：`version_no = max+1`，旧版本 `retired_at=now()`，`purge_after = retired_at + 90d`。
- 并发轮换：对 `shop_credential` 行加 `SELECT ... FOR UPDATE`，或乐观锁 `version`。
- 同一店铺同 `kind` 允许多条（例如 `access_token` 与 `refresh_token` 分开存），但**推荐合并为一条 `oauth2`**，`values` 里放多个键。

### 7.3 审计

所有以下动作写 `credential_audit`：`create / read / check / refresh / rotate / revoke / disable / purge`。
- `detail` 只放非敏感信息：`{"kind":"oauth2","version":2,"changed_fields":["access_token"]}`。
- **禁止**记录 `values` 的任何片段（包括前 4 位）。

### 7.4 幂等中间件

- 读 `Idempotency-Key` 头，`scope` = 路由模板（如 `POST:/api/v1/admin/shops`）。
- 先 `INSERT ... ON CONFLICT DO NOTHING` 占位（status=processing）。
- 已存在且 `completed` → 直接返回存的响应。
- 已存在且 `processing` → 返回 409 `10006`（或让客户端重试）。
- 请求体哈希不一致 → 409 `10006`。
- 完成后写 `response_code/response_body`。

### 7.5 文件上传

- 直传对象存储：后端签发 presigned PUT URL，前端直传，避免大文件过应用内存。
- 或小文件走 `multipart`（≤ 10MB），后端流式写入。
- 校验：MIME 白名单（image/jpeg,png,webp；application/pdf）、大小上限、扩展名与 MIME 一致。
- 存 `file_object`，返回 `id` + `url`。

## 9. 验收清单

```bash
# 1. 建店铺
curl -X POST localhost:8080/api/v1/admin/shops -H "Authorization: Bearer $T" \
  -H 'Content-Type: application/json' \
  -d '{"platform_id":1,"name":"测试店","external_shop_id":"S001","currency":"CNY","timezone":"Asia/Shanghai"}'

# 2. 录凭据
curl -X POST localhost:8080/api/v1/admin/shops/1/credentials -H "Authorization: Bearer $T" \
  -d '{"kind":"oauth2","label":"主账号","values":{"access_token":"SECRET-XYZ"},"refresh_strategy":"auto"}'

# 3. 数据库里必须是密文
psql "$DSN" -c "select encode(cipher_text,'hex') from credential_version limit 1;" | grep -v SECRET

# 4. 接口不能回显明文
curl -s localhost:8080/api/v1/admin/shops/1/credentials -H "Authorization: Bearer $T" | grep -c SECRET   # 0

# 5. 日志里不能有明文
grep -r "SECRET-XYZ" logs/ || echo "OK"

# 6. 轮换
curl -X PUT localhost:8080/api/v1/admin/credentials/1 -H "Authorization: Bearer $T" \
  -d '{"values":{"access_token":"SECRET-ABC"}}'
psql "$DSN" -c "select version_no, retired_at is null from credential_version order by version_no;"
```

| # | 验收项 | 通过标准 |
|---|---|---|
| 1 | 加密落库 | 直查 DB 无明文 |
| 2 | 接口脱敏 | 响应只有 fingerprint，无任何明文片段 |
| 3 | 日志脱敏 | 全文检索明文 0 命中 |
| 4 | 版本链 | 轮换后 v1.retired_at 有值，v2 生效 |
| 5 | AAD 防调包 | 把 v1 密文塞进 v2 解密失败 |
| 6 | 审计 | 每次 read/rotate 都有记录，且无敏感信息 |
| 7 | 幂等 | 同 `Idempotency-Key` 两次只建一条 |
| 8 | 数据权限 | 运营只能看到自己负责的店铺 |
| 9 | 文件上传 | 超 10MB 或非法 MIME 被拒 |

## 10. Gate A 评审关注点

- 一个店铺多条凭据 vs 一条凭据多个字段，哪种更好维护
- 主密钥轮换的具体流程（先解密再加密，还是双写过渡）
- 幂等中间件的性能开销（每个写请求多一次 Redis/DB 往返）
- 文件直传 vs 后端中转的安全边界
