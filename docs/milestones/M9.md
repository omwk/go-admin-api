## 1. 目标

让「调用 API」这件事能收钱、能对账、不超支。核心是**预扣 + 幂等 + 对账**三件套。

## 2. 范围

1. 表：`wallet / wallet_txn / pricing_plan / subscription / recharge_code / billing_statement / billing_reconcile_diff / usage_daily`（迁移 `000012_billing_init`）
2. 钱包与流水（只追加）
3. 冻结 / 提交 / 释放
4. 套餐与订阅
5. 用量聚合（日）
6. 日终对账 + 差异告警
7. 充值（人工 + 兑换码）
8. 账单
9. 接入 M8 网关的收费钩子

## 3. 不做

- 不做在线支付（微信/支付宝/Stripe）
- 不做发票
- 不做退款审批流
- 不做多币种结算（只记录币种）
- 不做阶梯定价（先线性单价 + 套餐）

## 5. 关键设计（摘要）

- 冻结用条件 UPDATE，影响行数 0 = 余额不足。
- 幂等键 = `trace_id`（冻结）、`trace_id:commit` / `trace_id:release`。
- `wallet_txn` 只追加，DB 层收回 UPDATE/DELETE 权限。
- 计费组件故障 → **fail closed**（503），不免费放行。
- 对账每日 02:00，差异写 `billing_reconcile_diff` 并告警。
- 单价不足 1 分用套餐包表达，不引入小数。

## 6. 接口清单

### M9a 实际接口与字段

本批只实现资金、逐调用预扣及恢复；下方总体规划中的权益、调账、对账和账单接口尚未发布。以本节、ADR-023 和本次 M9a 指令为准，旧示例中的 trace_id 扣费身份由服务端 call_id 替代。

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | `/api/v1/admin/wallets` | 为本人应用创建零余额 CNY 钱包；body: app_id | `billing:wallet:recharge` |
| GET | `/api/v1/admin/wallets` | 本人应用钱包，按 id 倒序，最多 100 项 | `billing:wallet:list` |
| GET | `/api/v1/admin/wallets/{id}` | balance_cents / available_cents / frozen_cents / currency / version | `billing:wallet:list` |
| GET | `/api/v1/admin/wallets/{id}/txns` | 最近 100 条只追加流水，含类型、金额、余额快照、call_id、occurred_at | `billing:wallet:list` |
| POST | `/api/v1/admin/wallets/{id}/recharge` | 人工充值；body: amount_cents（正 int64 分）、note（必填） | `billing:wallet:recharge` |
| POST | `/api/v1/admin/recharge-codes` | amount_cents、count（1–100）、可选 expires_at；明文只交付一次 | `billing:wallet:recharge` |
| GET | `/open/v1/balance` | 当前应用真实钱包余额；不占业务配额、不计量 | HMAC + 当前应用/key 门禁 + 限流 |
| POST | `/open/v1/recharge-code` | body: code；已使用/过期/跨租户统一 400/90301 | HMAC v2 + 限流 |
| GET | `/open/v1/calls/{call_id}/result` | 本应用原调用结果、币种与原收费金额；重验当前订单授权/owner scope | HMAC + 当前授权 + 限流 |
| POST/PUT | `/api/v1/admin/api-routes[/{id}]` | 既有路由增加 price_cents、units_per_call、currency；更新需 version | 既有 route:create/update |

- 管理写接口必须带 Idempotency-Key，同键同请求返回原回执，不同内容返回 409/10006。兑换码生成重放只返回 {"delivered":true}，不持久化明文。
- 路由只允许 free（price_cents=0）或 per_call（正整数 price_cents × units_per_call）；金额乘法溢出拒绝。仅 CNY。未发布 package/权益回落。
- 付费业务请求必须使用签名 v2：在 v1 六字段签名串后依次追加 LF、v2、LF、X-App-Id、LF、Idempotency-Key，无末尾 LF；请求头 X-Signature-Version=2。免费请求保留 v1。幂等键 1–128 字符，仅字母、数字及 ._:-；每次重试使用新 nonce。
- 同应用签名幂等键唯一映射到原 call_id；处理中 409/10004、异参 409/10006、完成重试复用原结果和价格。X-Request-Id 仅观测。回执读取不会再次扣款或计量。
- 独立公开 DTO/OpenAPI：`internal/modules/gateway/openapi.yaml`。统一安全错误不返回内部异常、他人余额或提交的兑换码。

## 8. 验收清单

```bash
# 充值 100 分
curl -X POST localhost:8080/api/v1/admin/wallets/1/recharge -H "Authorization: Bearer $T" \
  -d '{"amount_cents":100,"note":"测试"}'

# 余额
curl -s localhost:8080/api/v1/open/balance -H "X-App-Id: $APP_ID" ... | jq .data.balance_cents  # 100

# 并发扣费：单价 5 分，30 个并发
seq 30 | xargs -P 30 -I{} ./call.sh    # 20 个 200，10 个 402
psql "$DSN" -c "select balance_cents, frozen_cents from wallet where id=1;"   # 0, 0

# 上游失败释放
MOCK_UPSTREAM=500 ./call.sh
psql "$DSN" -c "select balance_cents from wallet where id=1;"   # 不变

# 幂等
./call.sh --trace-id fixed-123  (两次)
psql "$DSN" -c "select count(*) from wallet_txn where idempotency_key='fixed-123';"  # 1

# 对账
psql "$DSN" -c "delete from wallet_txn where id=(select max(id) from wallet_txn where type='commit');"
make reconcile
psql "$DSN" -c "select * from billing_reconcile_diff;"   # 有差异记录

# 兑换码
CODE=$(curl -X POST localhost:8080/api/v1/admin/recharge-codes -H "Authorization: Bearer $T" \
  -d '{"amount_cents":500,"count":1}' | jq -r '.data[0]')
curl -X POST localhost:8080/api/v1/open/recharge-code -H "..." -d "{\"code\":\"$CODE\"}"
curl -X POST localhost:8080/api/v1/open/recharge-code -H "..." -d "{\"code\":\"$CODE\"}"  # 90301
```

## 11. M9a 模型、事务及恢复

迁移为 `000019_billing_wallet`（实施时最大已合并号为 000018）。不修改已合并迁移。

| 载体 | 本批实际字段与约束 |
|---|---|
| wallet | tenant_id、app_id、currency、balance_cents、frozen_cents、version、status、updated_at；唯一 (app_id,currency)，0≤frozen≤balance |
| wallet_txn | topup/freeze/settle/release/adjust/refund 类型；正操作额（adjust 可带符号）、balance/frozen delta、前序版本对应的余额快照、call_id、全局唯一幂等键、请求摘要、actor_id、note、occurred_at；只追加触发器拦截 UPDATE/DELETE/TRUNCATE，并撤销 PUBLIC 修改权限 |
| call_charge | call_id 主键；tenant/app/wallet/currency、route/version、单价/单位/预扣快照、reserved→settled/released/expired 互斥终态、actual_cents、创建/截止/完成时间 |
| recharge_code | 高熵随机码仅保存 SHA-256 摘要；金额、币种、租户、有效期、使用应用和时间、创建人；标已用+充值+流水同事务 |
| api_route / api_call | 路由新增固定价格；调用保存原收费快照、签名请求幂等键及指纹；唯一 (tenant_id,client_id,idempotency_key)；api_call_log 保存本次实际费用 |

balance 是账面余额 B，available=B−frozen。冻结只增加 F；结算减少 B 的 actual 和 F 的 pre；释放只减少 F。冻结 5、结算 3 时 B 减 3，F 减 5，差额 2 自动恢复可用额。本批不接受 actual>pre 的追加收费。

资金准入以 PG 带归属、币种、状态和余额谓词的条件 UPDATE 裁决，不靠先查余额、Go mutex 或 Redis 锁。所有余额变化与只追加流水在同一 PG 事务内；同操作幂等检查后只可能整笔提交或整笔回滚。管理人工充值使用不可重复的命令身份；本批没有钱包状态编辑/调账接口。

Start 事务包含调用意图/processing 日志、call_charge、技术日/月配额、freeze 流水与冻结额；提交后才进入业务。Finish 事务包含调用结果、终态日志、settle/release 流水与余额、唯一成功 meter；提交后才返回成功。收费公开端口使用同一个 db.DB 的事务 context，嵌套 Transaction 复用外层事务。这样 meter 失败会同时回滚结算，不会出现“先提交 M8 计量、后单独扣款”的裂缝；事务内无外部 IO。

统一锁序为 call → charge → quota（日/月）→ wallet，缺项跳过。幂等命令锁仅串行化操作身份；资金安全始终由条件 UPDATE 和数据库约束保证。提交回执丢失按原 call_id 读取调用、收费终态、流水及成功 meter，核实完整回执后才返回。

沿用网关恢复 worker，每分钟扫描过期 processing 调用，使用同一 Finish 事务标失败并将 reserved 预扣转 expired/release。若成功已持久化则保持 settled；迟到 Finish 与恢复竞争时由调用/charge 行锁裁决，只允许一个终态。这里只恢复悬挂预扣，不实现 M9b 的三方对账。

财务流水、call_charge、兑换凭据与调用回执不进入普通日志清理；保留至少三年，未决不清理。本批不新增任何财务删除任务。只实现 M9a，M9b/M9c 保持未开始。
