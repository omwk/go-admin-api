## 1. 目标

订单是同步链路里**要求最高**的资源：不能漏、不能重、状态要可追溯、PII 要加密。

## 2. 范围

1. 表：`sales_order / order_item / order_address / order_status_history`（迁移 `000007_order_init`）
2. 订单增量同步（复用 M3 编排，新增 order upserter）
3. 统一状态机 + 原始状态并存
4. 订单查询/详情/导出
5. 收货信息加密与二次授权查看
6. 单笔重同步、消失订单标记
7. Webhook 接收（P2，可延后到 M5 末尾）

## 3. 不做

- 不做退款/售后流程（只同步状态）
- 不做订单编辑（改地址、改价）
- 不做发货（调平台发货接口）
- 不做对账（平台账单 vs 订单金额）
- 不做多币种换算

## 5. 关键设计

### 5.1 统一状态机

```
pending_payment ──▶ pending_shipment ──▶ shipped ──▶ completed
       │                    │               │
       └──▶ closed          └──▶ refunding ─┴──▶ refunded
```

允许的流转（白名单，写死在 `order.StatusMachine`）：

| from | 允许的 to |
|---|---|
| `pending_payment` | `pending_shipment`, `closed` |
| `pending_shipment` | `shipped`, `refunding`, `closed` |
| `shipped` | `completed`, `refunding` |
| `completed` | `refunding` |
| `refunding` | `refunded`, `completed` |
| `closed` / `refunded` | （终态，不可再变） |

- 同步时若平台状态映射出的目标状态**不允许**从当前状态流转，**不报错**：记录 `order_status_history(source=sync, note='illegal transition')`，状态保持不变，产生 warn 指标。
- 手动操作（如人工标记完成）走同一状态机，非法返回 `50301`。
- `unknown` 状态允许流转到任何状态（用于修复）。

### 5.2 增量同步

- 水位线：`sync_cursor.cursor_value` = 上次成功的最新 `updated_at`（平台时间）。
- **回看窗口 7 天**：每次从 `watermark - 7d` 开始拉，靠幂等去重。防平台延迟推送漏单。
- 订单详情必须拉全（列表接口通常不含明细），因此：列表页只取 ID + 时间 → 逐条调详情 → 落 raw。
- 详情拉取限流更严，单 run 最多 200 条，超出续跑。

### 5.3 PII 加密

- `receiver_name / phone / address` 整体加密，AAD = `tenant:order:{order_id}`。
- 明文只在「查看完整信息」接口中解密，要求权限 `trade:pii:read`，且写审计（含操作人、订单号、时间）。
- 列表页展示脱敏：`张*`、`138****1234`、`浙江省杭州市***`。
- `region_hint` 存省份明文，用于统计。

### 5.4 查询

- 主表 `sales_order`，明细按需 join（详情才查）。
- 索引：`(tenant_id, shop_id, status, placed_at desc)`、`(tenant_id, placed_at desc)`、`(tenant_id, buyer_nick)`。
- 金额筛选用 `total_amount_cents between ?`。
- `ext` 里的平台字段筛选走 GIN（谨慎使用，必须限定店铺）。

### 5.5 消失订单

平台侧删除的订单（API 返回 not_found）：
- 不物理删除，`ext.vanished = true`，`ext.vanished_at = now()`。
- 列表可筛 `vanished=true`。
- 统计时排除。

## 8. 验收清单

```bash
make seed-orders ORDERS=100000

# 列表性能
ab -n 200 -c 10 "localhost:8080/api/v1/admin/orders?shop_id=1&status=shipped" -H "Authorization: Bearer $T"

# 状态机
curl -X POST localhost:8080/api/v1/admin/orders/1/status -H "Authorization: Bearer $T" \
  -d '{"status":"pending_payment"}'        # 从 shipped 回退 → 50301

# PII
curl -s localhost:8080/api/v1/admin/orders/1 | jq '.data.receiver'   # 张*
curl -s localhost:8080/api/v1/admin/orders/1/address -H "Authorization: Bearer $T" | jq '.data.phone'
psql "$DSN" -c "select count(*) from audit_log where action='order.pii.read';"   # >= 1

# 加密
psql "$DSN" -c "select phone_cipher from order_address limit 1;" | grep -c "138" # 0

# 漏单补齐
psql "$DSN" -c "update sync_cursor set cursor_value = cursor_value - interval '1 day' where resource_type='order';"
curl -X POST localhost:8080/api/v1/admin/sync-jobs/2/run -H "Authorization: Bearer $T"
```

| # | 验收项 | 通过标准 |
|---|---|---|
| 1 | 幂等 | 重复同步订单数不变 |
| 2 | 明细一致 | 明细条数/金额与 fixture 一致 |
| 3 | 状态机 | 非法流转被拒；同步遇到非法流转不崩 |
| 4 | 状态历史 | 每次变更一条，时间用平台时间 |
| 5 | 漏单 | 回看窗口能补回 |
| 6 | PII | 库里密文；接口默认掩码；解密留痕 |
| 7 | 性能 | 10 万订单 P95 < 400ms |
| 8 | 导出 | 3 分钟内完成 |
| 9 | vanished | 平台删除后标记，不物理删 |

## 9. Gate A 评审关注点

- 7 天回看窗口是否够（平台延迟最坏情况）
- 列表页拉详情的 N+1 风险（限 200 条/run 够不够）
- 状态机遇到平台「跳状态」怎么办（当前策略是不变 + 记录，是否可接受）
- PII 解密的审计粒度（每次查看都记是否太吵）
