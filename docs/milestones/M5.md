## 0. 已裁决的边界（不要重新讨论）

| 议题 | 结论 |
|---|---|
| 状态模型 | 正交维度（lifecycle/fulfillment/payment/after_sales/cancel）+ 兼容展示投影 |
| 状态变更 | 命令走单步白名单；快照允许跨步只录事实；纠正须人批准 + 证据 |
| 订单身份 | 平台不可变实例身份；展示单号另存，不作唯一键 |
| 幂等 | 至少一次投递 + 聚合幂等；hash 仅做同版本去重 |
| 能力分级 | A/B/C 三级，承诺随级别降级，缺级不得宣称强保证 |
| PII | 逐字段信封、独立 nonce、AAD 绑 tenant/order/field/version；raw 信封加密 |
| PII 查看 | 5 分钟内重认证 + 专属权限 + 逐次审计；默认全掩码 |
| 金额 | 保留平台原值 + formula_delta/payment_delta；优惠按最大余数法分摊 |
| 售后 | 只存摘要（累计退款/状态/时间/拒绝原因），不建流程 |
| 同步 | 时间水位 + 回看窗口 + 持久详情待办；双进度分开统计 |
| 迁移 | `000010`（取当前最大号 +1） |
| 测试分片 | 新增 `order` 组，守卫同步更新 |

### M5a 实现计划与内部契约

本轮仅交付聚合写入，不注册 HTTP 或同步 Handler，不提供 PII 读取。以下内部契约以 ADR-019 为准，取代本卡旧版单状态及整行地址加密示例。

| 入口 | 契约 |
|---|---|
| `order.NewUpserter(sealer, MoneyPolicy)` | 显式传入公式/结清差额阈值（最小货币单位），不新增配置或依赖 |
| `Upserter.Apply(ctx, tx, Snapshot) (Result, error)` | 调用者短事务；先锁检查点，再调用；错误必须向外传播。事务必须同时包含目标聚合、持久处置、检查点 |
| `Snapshot.ExpectedVersion` | 新单为 0；已有单 CAS；冲突使用 409/10409 |
| `Snapshot.Revision` | 可空的上游可比较版本；hash 仅作同 revision 或同 raw/映射版本的去重，不能判定新旧 |
| `Snapshot.Items` | nil 保留；完整且数量/分页/稳定身份/金额校验通过才替换；显式确认完整空集合才清空；不完整整单隔离 |
| `Snapshot.Address` | nil 保留；三字段各自 Seal；AAD=`tenant:order:field:address_revision`，key_version 单独存储；不输出明文 |
| 状态决策 | 五维事实；快照允许跨步，只记直接观测；危险回滚须更高 revision、权威详情、平台纠正能力和人工批准 |
| 金额 | formula_delta=total-(goods+shipping-discount)，payment_delta=paid-total；仅结清支付检查 payment 阈值；超阈值整单隔离 |
| 分摊 | 明细 AmountCents 为扣除行优惠后的金额，订单优惠另列；显式声明参与范围；平台分摊优先，本地最大余数法同余数按 external_item_id 排序 |
| 处置 | 冲突追加 `order_status_history(event_kind=conflict)`，金额/完整性等隔离复用 quarantine_record，均只存安全原因与 RawRef；基础设施错误整事务回滚；同 raw 新映射重解释和仅金额纠正也追加聚合审计事件 |

## 5. 关键设计

### 5.1 统一状态机

```
pending_payment ──▶ pending_shipment ──▶ shipped ──▶ completed
       │                    │               │
       └──▶ closed          └──▶ refunding ─┴──▶ refunded
```

允许的流转（白名单，写死在 `order.StatusMachine`）：

| from | 允许的 to |
|---|---|
| `pending_payment` | `pending_shipment`, `closed` |
| `pending_shipment` | `shipped`, `refunding`, `closed` |
| `shipped` | `completed`, `refunding` |
| `completed` | `refunding` |
| `refunding` | `refunded`, `completed` |
| `closed` / `refunded` | （终态，不可再变） |

- 同步时若平台状态映射出的目标状态**不允许**从当前状态流转，**不报错**：记录 `order_status_history(source=sync, note='illegal transition')`，状态保持不变，产生 warn 指标。
- 手动操作（如人工标记完成）走同一状态机，非法返回 `50301`。
- `unknown` 状态允许流转到任何状态（用于修复）。

### 5.2 增量同步

- 水位线：`sync_cursor.cursor_value` = 上次成功的最新 `updated_at`（平台时间）。
- **回看窗口默认 15 分钟**：每次从 `watermark - order_lookback_seconds` 开始拉，可配置；冻结窗口与分页 token 独立于完成水位，只有窗口内详情全部完成才推进水位。
- 订单详情必须拉全（列表接口通常不含明细），因此：列表页只取 ID + 时间 → 逐条调详情 → 落 raw。
- 详情拉取限流更严，单 run 最多 200 条，超出续跑。

### 5.3 PII 加密

- `receiver_name / phone / address` 整体加密，AAD = `tenant:order:{order_id}`。
- 明文只在「查看完整信息」接口中解密，要求权限 `trade:pii:read`，且写审计（含操作人、订单号、时间）。
- 列表页展示脱敏：`张*`、`138****1234`、`浙江省杭州市***`。
- `region_hint` 存省份明文，用于统计。

### 5.4 查询

- 主表 `sales_order`，明细按需 join（详情才查）。
- 索引：`(tenant_id, shop_id, status, placed_at desc)`、`(tenant_id, placed_at desc)`、`(tenant_id, buyer_nick)`。
- 金额筛选用 `total_amount_cents between ?`。
- `ext` 里的平台字段筛选走 GIN（谨慎使用，必须限定店铺）。

### 5.5 消失订单

M5b 仅在平台原始响应含明确删除/不存在信号时设置 `vanished_at` 和 `vanish_reason`，并追加 `visibility: active → vanished` 历史及 RawRef；增量缺席与传输失败不触发删除。

- 再次观测到完整订单时清空两列，追加 `visibility: vanished → active` 历史；普通 raw 重放不恢复 visibility，明确删除 raw 可标记。
- 列表默认排除，`include_vanished=true` 时包含。
- 历史成交额/单量统计始终包含 vanished，平台不可见不改变历史事实。两处口径详见 `api/openapi/order.yaml`。
